= 项目文档导航（开发文档）

本文件是 ctool4j **开发文档**的导航入口（文档目录树即站点导航），逐级指向各模块与功能文档的固定落点。

* *本目录只承载开发文档*：以「本库怎么实现、为什么这样设计」为内容（模块全景、设计方案、取舍、已知限制、依赖关系与兼容性）。
  「引用本库的项目怎么引入、怎么用」是**另一套文档**——link:use/README.adoc[doc/use/]（使用文档，整体开放为静态服务），两者**隔离、互不复制内容**：
  模块 README 里已有的能力清单与用法在那边不重复（那边以链接指回），互为第二真源即漂移。

== 文档分层（先看这里）

* *javadoc 即文档，且按层次分工*：源类**类上**写定位、能力目录与设计文档链接（不写实现细节与方案取舍）；**方法/字段上**写该 API 的契约
  （参数语义、返回值、异常、边界与默认值、空值语义、易误用点），不写"为什么这样设计"与备选方案；跨方法的设计内容（方案与取舍、兜底、
  适用范围、已知限制）进功能级设计文档，代码与文档双向互引。测试类**类上写总结**（测试设计思路与依据、覆盖与未覆盖、
  用例总览/分类/编码与逐个用例精简总结）；**测试方法上写详细设计**（引用用例编码、测试意图、测试范围、测试意义、断言取舍）。
* *模块级说明（模块职责、能力清单、核心类）只在模块 README*：各模块目录下的 +README.md+，由根 link:../README.adoc[README] 的模块文档索引汇总。
* *功能级文档（跨类设计）只在 +doc/design/<模块>/+*：方案取舍、兜底策略、适用范围、已知限制与波及影响，按功能命名、不与源文件同名。
* *依赖关系唯一视图*：模块间依赖只写 link:dependency.adoc[dependency.adoc]。
* *不重复内容*：同一事实只有一个落点，其余位置以链接指回；模块 `doc/` 下不再另设索引页（导航以本文件为树根）。

== 约定

* *字段说明*：如无特别说明，文档中的模块名即 Maven 模块目录名（+ctool4j-xxx+）。
* *依赖落点*：模块间增删依赖须在同一提交内同步更新 link:dependency.adoc[dependency.adoc]。
* *版本与变更*：源文件版本在各源码 javadoc 的 +@version+ 中维护；全项目变更记录统一在 link:../CHANGELOG.adoc[CHANGELOG.adoc]（按发布 tag 分组，条目格式见 link:../agent/AGENTS-PROJECT.MD[项目特有规范]「变更日志的组织与条目形态」）。
