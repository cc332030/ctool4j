= 模块间依赖关系

本文件是 ctool4j **模块间依赖关系的唯一视图**（多模块项目的固定落点，见远端规范
`specs/general/doc-design.adoc`「依赖关系文档（模块间依赖的唯一视图）」）。

只回答一个问题：**这个模块能不能直接用某个模块的能力**（谁依赖谁、方向如何）。据此判断"新增依赖该不该加、是不是已经在依赖里"，
读完即止、不再解析依赖树。第三方库的版本与传递关系属 `pom.xml` 与 BOM 的范围，本文件**不复制**（避免第二真源）。

== 阅读方式

* 依赖关系**以 UML 图为主**（Mermaid `graph`）：虚线开放箭头表示依赖，**箭头由依赖方指向被依赖方**（`A -.-> B` 读作「A 依赖 B」）；
  被多条箭头汇聚的模块即公共基础模块。
* **模块清单表为本文件的核对面**：`模块 | 直接依赖 | 说明/约束` 逐行可核（图的完整覆盖、方向、作用域约束都在表中如实列出）。
* 依据：ISO/IEC/IEEE 42010（架构描述须可支持架构决策与影响判断）、UML（OMG，依赖关系记法）、ISO/IEC/IEEE 29148（可追溯性）。
* 图的渲染：Mermaid 由 Git 平台 / 支持 Mermaid 的 AsciiDoc 渲染器 / IDE 插件解析，图源为下述文本块，可随代码演进在提交里逐行 diff。
* 维护：模块间增删依赖、新增/拆分模块后，**同一提交内**更新本文件；与构建文件冲突时以 `pom.xml` 实际解析结果为准并立即修正本文件。

== 构建基础设施与聚合模块

构建基础设施（BOM / 聚合 pom）位于依赖链的旁侧：业务模块**通过 `ctool4j-dependencies`、`ctool4j-bom` 统一版本**（import 而非传递依赖），
业务项目引入 `ctool4j-bom` 即可获得一致的第三方版本；四个聚合 pom 只是 `<modules>` 容器，除模块结构外不引入依赖。

=== 传递依赖的可用范围（易误用点）

模块 A 依赖 B 时，B 的 `compile` 依赖会传递到 A，但**以下三类不传递**，B 中"仅靠 provided/optional 能满足"的能力，
到 A 处会缺依赖、编译或运行失败——此时应由 A 显式声明，**不属于重复声明**：

* `provided`：如 `ctool4j-web` 的 spring-boot-starter-web、`ctool4j-mybatis-base` 的 mybatis-plus-boot-starter 与 `ctool4j-redis`
  （前者依赖由使用方提供）。
* `optional`：如 `ctool4j-core` 的 guava、java-uuid-generator、jnanoid、ulid-creator、httpmime。
* `test`：如 `ctool4j-mybatis-processor` 的 ctool4j-mybatis（仅供其测试使用）。

已在**直接或间接**依赖中的模块，**不得再在依赖清单里重复声明**（判定以本文件为准）。

== 依赖方向与分层约束

* 依赖方向单向、无环：`definition → core → spring → （web / redis / transaction / ...）→ 应用层`；下层不得反向依赖上层。
* `ctool4j-definition` 与 `ctool4j-http-base` 是"零模块依赖"底座，任何模块都可安全依赖。
* 容器抽象层保持单向：`http-base → http-javax / http-jakarta`、`spring-base → spring-javax / spring-jakarta`、
  `spring-security-base → spring-security-javax / spring-security-jakarta`；两侧适配模块只被上层依赖，不得反向依赖，
  同一侧的 `-javax` 与 `-jakarta` 之间不互相依赖。是否登记进构建见 `agent/AGENTS-PROJECT.MD`（当前 Spring 5.3 / Boot 2.x
  矩阵下 `ctool4j-spring-jakarta` 与 `ctool4j-spring-security-jakarta` **不进** `<modules>`）。
* 认证链保持单向：`web → auth-base → auth-spring`；`auth-spring` 另依赖 `spring-security`，不得反向。
* 中间件模块（log / mybatis / nacos / mq / job / file / doc）只依赖基础层，**彼此之间不互相依赖**；
  组合使用（如 `ctool4j-feign` + `ctool4j-log-base`）由使用方按需引入。
* 请求链路保持单向：`web → feign`、`feign → log-base`；`auth-base` 依赖 `web` 与 `cache`（会话存储），
  `auth-spring` 再叠 `spring-security`——不得反向依赖认证模块。
* `ctool4j-spring` 依赖 `ctool4j-autowired-processor`（编译期注解处理器，非运行时依赖）；
  `ctool4j-mybatis-processor` 对 `ctool4j-mybatis` 的依赖为 test 作用域（该依赖不随处理器传递到使用方）。
