== 1. 功能说明

`CTag` 为接口/Controller 级纯文档注解，命名对应 OpenAPI3 中 Swagger/OpenAPI2 `Api` 的替代注解 `Tag`（前缀 c），
标注在 Controller/接口类上，说明该类接口的分组（tag）与描述。

- `value()`：分组标签内容（作为该 Controller 的显示分组名），默认 ""，支持简写 `@CTag("内容")`
  （替代了原先的 `name()`，对应 OpenAPI3 `Tag.name` / OpenAPI2 `Api.tags`）
- `description()`：分组标签描述（对应 OpenAPI3 `Tag.description` / OpenAPI2 `Api.value`），默认 ""

== 2. 设计要点

=== 2.1 替代 OpenAPI2 Api

- 项目以 C 前缀自定义注解替代 Swagger 注解（同 CSchema 替代 `@ApiModelProperty`），`@CTag` 替代类级 `@Api`。

=== 2.2 纯文档

- 仅提供文档元数据，不参与运行时校验（无 @Constraint）。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| value 为空 | 由插件按实际需要处理，不强制分组名 |
| description 为空 | 不覆盖已有描述 |

== 4. 适用范围

=== 4.1 适用场景

- Controller/接口类需要分组名与描述时标注 `@CTag`，由 openapi2 的 `CTagAnnotationPlugin` 落地分组。

== 5. 已知限制与取舍

- openapi2（springfox）对 tag 描述的渲染受框架限制，`description` 以能落地的位置为准。
