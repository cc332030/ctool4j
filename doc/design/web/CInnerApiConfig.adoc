= CInnerApiConfig 设计文档

Version: 1.2
LastModified: 2026-09-09
模块：ctool4j-web
类：com.c332030.ctool4j.web.config.CInnerApiConfig
状态：已落地
适用范围：内部接口 IP 白名单配置

== 1. 功能说明

`CInnerApiConfig` 为内部接口 IP 白名单配置属性类，`@ConfigurationProperties("inner-api")` + `@Data`，
由 Spring Boot 绑定 `inner-api.*` 前缀配置项。所有标注 `@CInnerApi` 的内部接口共用本配置。

字段：

- `allowedIps`：内部接口允许访问的 IP/IP 段(CIDR)白名单，默认空（空则全部放行）

== 2. 设计要点

=== 2.1 配置绑定

- 使用 `inner-api` 前缀绑定（与 `cors`/`logging.request-log` 等既有配置风格一致）。
- 由 `CSpringConfiguration` 的 `@ConfigurationPropertiesScan`（扫描 `com.c332030.ctool4j`）自动注册为 Bean。

=== 2.2 白名单语义

- 仅白名单：命中 `allowedIps` 中任一 IP/IP 段(CIDR)才放行，否则拒绝。
- 空名单即放行：未配置白名单时不限制（避免误伤内部调用），由使用方按需配置。

=== 2.3 规则格式

- 单个 IPv4：如 `127.0.0.1`。
- CIDR 网段：如 `10.0.0.0/8`、`192.168.1.0/24`。
- 由 `CIpUtils`（`doc/design/spring/CIpUtils.adoc`）解析判断。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 未配置 `allowed-ips` | 默认空集合，拦截器视为全部放行 |
| 规则非法（如非 CIDR、前缀越界） | 由 `CIpUtils` 记录日志并跳过该规则，不影响其它规则 |

== 4. 适用范围

=== 4.1 适用场景

- 通过 `inner-api.allowed-ips` 配置内部接口允许访问的内网 IP/IP 段。

=== 4.2 不适用/边界场景

- 仅配置模型，实际生效依赖 `CInnerApiInterceptor` 读取并校验。

== 5. 已知缺陷与不足 / 注意事项

=== 5.1 字段级

- `allowedIps`（配置键 `inner-api.allowed-ips`）：
  - **默认值语义（易误用/安全）**：默认空集合，语义为"全部放行"。若标注了 `@CInnerApi` 却**忘记配置白名单**，拦截器因空名单直接放行——等于没启用 IP 保护。使用者须意识到：**只有显式配置 `allowed-ips` 后 IP 白名单才真正生效**，这与直觉（标注=保护）相反，属易踩坑点。
  - 单值/多值：Set 支持多个元素，配置文件用列表或逗号分隔均可绑定。

=== 5.2 边界与约束

- 规则仅支持 IPv4 与 IPv4 CIDR；配置 IPv6 规则会被 `CIpUtils` 判为非法规则跳过（不会报错但等效于未命中，见 `CIpUtils.adoc`）。

=== 5.3 线程安全与变更生效

- 作为 Spring 单例 `@ConfigurationProperties` Bean，经 setter 绑定；运行期一般不再变更。若在运行期动态改写 `allowedIps` 集合引用，`CInnerApiInterceptor` 每次请求读取最新引用，可即时生效，但非线程安全的并发写需由使用方自行保证。

=== 5.4 波及影响

- 白名单为**全局唯一**，所有标注 `@CInnerApi` 的接口共用（取舍：不支持逐接口差异化名单）。调整白名单会同时影响全部内部接口的放行范围。
