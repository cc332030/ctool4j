== 1. 功能说明

`CErrorController` 为统一错误处理 Controller，`@RestController` + `@ConditionalOnMissingBean(ErrorController.class)`，
容器中无其它 `ErrorController` 时生效，`@RequestMapping("/error")` 处理错误跳转。

核心方法 `error(HttpServletRequest request)`：

- 从 `CRequestUtils.getErrorStatusCode(request)` 取请求中携带的状态码
- 存在异常属性（`RequestDispatcher.ERROR_EXCEPTION`）时记录 error 日志
- 状态码解析失败（直接访问 `/error`、状态码为空/非法）时兜底 `HttpStatus.INTERNAL_SERVER_ERROR`（500）
- 返回 `CStrResult.error(httpStatus)`（code 为状态码数字字符串，msg 为状态描述）

== 2. 设计要点

=== 2.1 条件装配

- `@ConditionalOnMissingBean(ErrorController.class)`：业务方自定义 ErrorController 时本类不生效。

=== 2.2 状态码兜底

- `CNumUtils.parseIntDefaultNull` 解析失败 → `HttpStatus.INTERNAL_SERVER_ERROR`。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 直接访问 `/error`（无 ERROR_STATUS_CODE） | 返回 500 |
| 状态码非法/无法解析 | 返回 500 |
| 存在异常属性 | 记录 error 日志（含堆栈） |

== 4. 适用范围

=== 4.1 适用场景

- 容器错误页统一重定向到 `/error` 时返回统一错误 JSON。

=== 4.2 不适用/边界场景

- 业务方自定义 ErrorController 时不生效。

== 5. 已知限制与取舍

- 返回结构固定为 `CStrResult<Void>`；状态码来自错误跳转携带的属性。

测试内容见 `doc/design/web/CErrorControllerTests.adoc`。
