== 1. 功能说明

`ConditionalOnMissingExceptionHandlerCondition`（`@CustomLog` + `@AllArgsConstructor`）为
`ConditionalOnMissingExceptionHandler` 注解的条件判断，实现 Spring `Condition`。

核心方法 `matches(ConditionContext, AnnotatedTypeMetadata)`：

- 从注解元数据读取要检查的异常类型 `value()`
- 取容器中所有 `ControllerAdvice` 标注的 bean
- 无任何 ControllerAdvice 时返回 true（启用默认 Handler）
- 遍历各 bean 方法，若任一方法用 `@ExceptionHandler` 处理了该异常类型，返回 false（禁用默认 Handler）
- 均未处理时返回 true（启用默认 Handler）

== 2. 设计要点

=== 2.1 反射遍历

- 用 `CReflectUtils.getMethods` 获取 bean 方法，检查 `@ExceptionHandler` 注解的 `value()` 是否包含目标异常类型。

=== 2.2 空安全

- beanFactory/beanMap 为空时按"无 ControllerAdvice"处理，返回 true 启用默认 Handler。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 注解不存在 | `Assert.notNull` 抛异常 |
| beanFactory 为 null | `Assert.notNull` 抛异常 |
| 无 ControllerAdvice | 返回 true，启用默认 Handler |
| bean 无方法 | 跳过该 bean，继续遍历 |

== 4. 适用范围

=== 4.1 适用场景

- 框架内置异常处理器的条件装配，避免与业务方自定义处理器冲突。

== 5. 已知限制与取舍

- 用反射遍历 bean 方法，性能开销可接受（仅 Spring 启动装配时执行一次）。

测试内容：无独立测试类（该 Condition 依赖 Spring 容器装配，行为由各异常处理器的条件装配集成场景间接覆盖）。
