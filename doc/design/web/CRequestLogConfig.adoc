== 1. 功能说明

`CRequestLogConfig` 为请求日志配置属性类，`@ConfigurationProperties("logging.request-log")` + `@Data`，
由 Spring Boot 绑定 `logging.request-log.*` 前缀配置项。

属性：

- `enable`：请求日志开关，默认 `false`
- `enableHeader`：请求头日志开关，默认 `false`（请求头可能含 Authorization、Cookie 等敏感信息，
  需时显式开启；token 等业务数据不受此开关影响，仍由业务数据区输出）
- `slowLogEnable`：慢请求日志开关，默认 `true`
- `slowLogMillis`：慢请求日志毫秒数，默认 3000
- `excludeUriPatterns`：排除的 URI 列表（支持通配符 `*`）

== 2. 设计要点

=== 2.1 配置绑定

- 使用 `logging.request-log` 前缀绑定，默认值即按安全默认（enable=false、enableHeader=false）。

=== 2.2 安全默认

- `enableHeader` 默认关闭，避免敏感请求头（Authorization/Cookie）泄露；业务数据区（token 等）
  不受该开关影响。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 未配置 `enable` | 默认 false，不记录请求日志 |
| 未配置 `enableHeader` | 默认 false，不输出请求头 |
| 未配置 `excludeUriPatterns` | 为 null，`isExcludeUri` 判空后返回 false（不排除任何 URI） |

== 4. 适用范围

=== 4.1 适用场景

- 通过 `logging.request-log.*` 配置请求日志开关、敏感头、慢请求阈值与排除 URI。

=== 4.2 不适用/边界场景

- 仅配置模型，实际生效依赖 `CRequestLogUtils`/拦截器等读取判断。

== 5. 已知限制与取舍

- `enableHeader` 与业务数据（token）解耦：业务数据区输出不受开关影响（有意设计）。
- `excludeUriPatterns` 支持 `*` 通配，通过 `CPatternUtils.getUrlCache` 预编译匹配。

测试内容：无独立测试类（CRequestLogConfig 为配置模型，由 `CRequestLogUtils` 等使用方测试间接覆盖）。
