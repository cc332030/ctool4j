== 1. 功能说明

`CRequestLogConfig` 为服务端 MVC 请求日志配置属性类，`@ConfigurationProperties("logging.request-log")` + `@Data`，
由 Spring Boot 绑定 `logging.request-log.*` 前缀配置项。公共属性（`enable`/`enableHeader`/`slowLogEnable`/`slowLogMillis`）继承自
`CRequestLogBaseConfig`（见 `doc/design/web/CRequestLogBaseConfig.adoc`），本类维护服务端特有属性：

- `excludeUriPatterns`：排除的 URI 列表（支持通配符 `*`）

继承自基类的属性：

- `enable`：请求日志开关，默认 `false`
- `enableHeader`：请求头日志开关，默认 `false`（请求头可能含 Authorization、Cookie 等敏感信息，
  需时显式开启；traceId/tenantId/userId 等业务数据不受此开关影响，仍由业务数据区输出；
  token/ip 与开关联动：开关开启时请求头已输出 Authorization/ip 不重复打印，开关关闭时业务数据区输出 token/ip 保证可见）
- `slowLogEnable`：慢请求日志开关，默认 `true`（默认启用，不受 enable 控制）
- `slowLogMillis`：慢请求日志毫秒数，默认 3000

== 2. 设计要点

=== 2.1 配置绑定

- 使用 `logging.request-log` 前缀绑定，默认值即按安全默认（enable=false、enableHeader=false）。

=== 2.2 公共属性继承

- `enable`/`enableHeader`/`slowLogEnable`/`slowLogMillis` 上移至 `CRequestLogBaseConfig`，本类仅保留服务端特有属性（排除 URI）。

=== 2.3 安全默认

- `enableHeader` 默认关闭，避免敏感请求头（Authorization/Cookie）泄露；业务数据区（token/ip）
  与开关联动：开关关闭时仍输出 token/ip，保证鉴权与来源信息可见。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 未配置 `enable` | 默认 false，不记录请求日志 |
| 未配置 `enableHeader` | 默认 false，不输出请求头 |
| 未配置 `excludeUriPatterns` | 为 null，`isExcludeUri` 判空后返回 false（不排除任何 URI） |

== 4. 适用范围

=== 4.1 适用场景

- 通过 `logging.request-log.*` 配置请求日志开关、敏感头、慢请求阈值与排除 URI。

=== 4.2 不适用/边界场景

- 仅配置模型，实际生效依赖 `CRequestLogUtils`/拦截器等读取判断。

== 5. 已知限制与取舍

- `enableHeader` 与业务数据（token/ip）联动：开关开启时请求头已输出 Authorization/ip，业务数据区不重复打印；开关关闭时业务数据区输出 token/ip 保证可见（有意设计）。
- `excludeUriPatterns` 支持 `*` 通配，通过 `CPatternUtils.getUrlCache` 预编译匹配。

测试内容：无独立测试类（CRequestLogConfig 为配置模型，由 `CRequestLogUtils` 等使用方测试间接覆盖）。
