== 用例设计思路与依据

=== 设计思路

- 按拦截器判断链路的各分支覆盖：handler 类型判定 → 注解识别（类/方法级）→ 白名单空/命中/未命中。
- 通过内部 Controller 桩类标注/不标注 `@CInnerApi`，配合 `HandlerMethod` 驱动 `preHandle`，用 `MockHttpServletRequest`/`MockHttpServletResponse` 模拟请求与响应。

=== 设计依据

- 依据功能设计对 `preHandle` 的约定：非内部接口放行、白名单空放行、命中放行、未命中返回 false 且写 403。
- 依据边界/分支覆盖：非 HandlerMethod、无注解、类级注解、方法级注解、白名单空、命中（含 X-Forwarded-For 首段）、未命中。

=== 覆盖场景与未覆盖

- 覆盖：非 HandlerMethod 放行；无注解放行；类级/方法级 `@CInnerApi` 识别；`@Inherited` 父类类级继承；白名单空放行；命中白名单放行（含 X-Forwarded-For 首段命中）；X-Forwarded-For 首段未命中拒绝；未命中拒绝并响应 403。
- 未覆盖：真实 Spring MVC 容器集成（由集成用例另行覆盖）、`@Inherited` 在真实代理(如 CGLIB)下的场景。

== 1. IP 白名单拦截

- 1.1 非 HandlerMethod（如静态资源）：直接放行
- 1.2 类/方法均无 `@CInnerApi`：放行
- 1.3 标记 `@CInnerApi` 但白名单为空：放行
- 1.4 方法级 `@CInnerApi` 命中白名单：放行
- 1.5 类级 `@CInnerApi` 命中白名单：放行
- 1.6 标记 `@CInnerApi` 未命中白名单：拒绝且响应 HTTP 403
- 1.7 方法级 `@CInnerApi` 经 X-Forwarded-For 首段命中：放行
- 1.8 方法级 `@CInnerApi` 的 X-Forwarded-For 首段未命中白名单：拒绝且响应 HTTP 403（仅信任首段）
- 1.9 子类继承 `@CInnerApi` 标注父类类（@Inherited 类级继承）命中白名单：放行
- 1.10 子类继承 `@CInnerApi` 标注父类类未命中白名单：拒绝且响应 HTTP 403
