== 1. 功能说明

`CCorsUtils`（`@UtilityClass` + `@CAutowiredScan`）为跨域处理的静态工具类，
持有 `@CAutowired` 注入的 `CCorsConfig config`，供 `CCorsFilter`/`CCorsInterceptor`/
`CCorsResponseBodyAdvice` 复用。

核心方法：

- `handleOptions(request, response)`：`enable=true` 且为 OPTIONS 预检请求时，以 204 状态码
  结束预检并返回 true；否则返回 false。预检的 CORS 响应头由 `handle`/`handleDo` 在处理链中先行设置。
- `handle(request, response)`：`enable=true` 时调用 `handleDo` 设置跨域响应头。
- `handleDo(request, response)`：按配置校验并设置跨域响应头。

== 2. 设计要点

=== 2.1 开启开关

- 由 `CBoolUtils.isTrue(config.getEnable())` 控制；未开启时不输出任何跨域头。

=== 2.2 handleDo 校验链

- 校验请求来源 header `Origin` 是否为空 → 是否同源 → 是否在 `allowedOrigins` 中 →
  请求方法是否在 `allowedMethods`（含 `*` 通配）中。
- 全部通过后设置响应头：
  - `Access-Control-Allow-Origin` 回显请求 Origin
  - `Access-Control-Allow-Headers`：`allowedHeaders` 含 `*` 时用 `*`，否则逗号连接
  - `Access-Control-Allow-Credentials`：固定 `true`
  - `Access-Control-Allow-Methods`：回显当前请求方法

=== 2.3 异常兜底

- `handle`/`handleOptions` 外层 try-catch 捕获 Throwable 记录 error 日志，避免跨域处理异常影响主流程。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 配置未注入（config 为 null） | NPE 被外层 try-catch 捕获，记录日志，跨域头不输出 |
| `handleDo` 校验链不通过（非同源/不在白名单/方法不允许） | 不设置任何跨域头，直接返回 |
| 请求无 `Origin` 头 | 视为非跨域请求，直接返回 |

== 4. 适用范围

=== 4.1 适用场景

- 跨域请求需要动态回显 Origin、按配置白名单放行来源与方法的场景。

=== 4.2 不适用/边界场景

- `enable=false` 时不做处理；`Origin` 为 null（非浏览器跨域）不处理。

== 5. 已知限制与取舍

- 采用"回显 Origin + 白名单校验"而非 `*` 通配，因此支持 `Allow-Credentials: true`（带凭据跨域）。
- `CUrlUtils.getHostWithPort` 归一化 Origin 后再与 HOST 比较判断是否同源。
- 预检请求的 CORS 头依赖 `handle`/`handleDo` 在处理链中先行设置，`handleOptions` 本身不再设置（有意设计）。
