== 用例设计思路与依据

=== 设计思路

- 覆盖 `handle` 的 error 为 null / 非 null 无扩展 / 非 null 有扩展三条分支。
- error 为 null 时回退到默认 500；error 非 null 时透传业务错误码并拼接扩展信息。

=== 设计依据

- 依据功能设计对 error 兜底、错误码透传、扩展信息拼接的约定。
- 依据测试方法（分支覆盖/边界）：error null、error 无 msgExtend、error 有 msgExtend。

=== 覆盖场景与未覆盖

- 覆盖：error 为 null 返回默认 500；error 非 null 无扩展返回错误消息本身；error 非 null 有扩展拼接 `msg: extend`。
- 未覆盖：真实 MVC 容器下的异常链路（当前直接调用 handler）。

== 1. 业务异常处理

- 1.1 error 为 null：返回默认 500 + 扩展消息（`handle_whenErrorNull`）
- 1.2 error 非 null 无扩展：透传错误码与错误消息（`handle_whenErrorWithoutMsgExtend`）
- 1.3 error 非 null 有扩展：追加扩展信息（`handle_whenErrorWithMsgExtend`）
