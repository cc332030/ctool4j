= CInnerApi 设计文档

Version: 1.0
LastModified: 2026-09-09
模块：ctool4j-definition
类：com.c332030.ctool4j.definition.annotation.CInnerApi
状态：已落地
适用范围：内部接口标记注解

== 1. 功能说明

`CInnerApi`：内部接口标记注解。

标注在 Controller 类或其接口方法上，将接口标记为"内部接口"。内部接口默认仅允许配置的内部 IP/IP 段(CIDR)访问，
由 ctool4j-web 的 `CInnerApiInterceptor` 在请求进入时读取，并结合 `CInnerApiConfig` 配置的白名单做校验。

== 2. 设计要点

- 支持类级（`ElementType.TYPE`）与方法级（`ElementType.METHOD`）标注：标在方法上仅该接口标记为内部接口；标在类上该类下所有接口方法均标记。
- `@Inherited`：标注在抽象父类类级时，子类自动继承（`isAnnotationPresent` 向上查找），无需在子类重复标注。
- 纯标记注解，无 `value`：IP 白名单由配置类统一提供，所有标注注解的内部接口共用同一份配置，避免逐接口维护 IP。
- 命名 `CInnerApi`（内部接口），与"标记为内部接口"语义一致；IP 白名单是拦截器对内部接口的默认保护，不体现在注解名。
- 声明放 ctool4j-definition 纯注解模块：不依赖 web/servlet，使 `CMpController`（mybatis-base，仅依赖 definition）等基类可直接标注而不引入 web 依赖。

== 3. 兜底设计

- 未配置白名单（`allowed-ips` 为空）时，拦截器直接放行，不影响正常内部访问。

== 4. 适用范围

=== 4.1 适用场景

内部管理类接口、继承 `CMpController` 的具体 Controller，需限制仅内网 IP 调用。

=== 4.2 不适用/边界场景

对外公开接口不应标注；若需接口对外可访问则不应标记为内部接口。

== 5. 已知缺陷与不足 / 注意事项

=== 5.1 易误用点

- **纯标记注解，不携带 IP**：想"给单个接口单独指定 IP"无法通过本注解表达，需靠 `CInnerApiConfig` 全局白名单（取舍：所有内部接口共用同一份白名单）。
- **标注 ≠ 立即收紧**：注解本身不产生拦截；需依赖 ctool4j-web 的 `CInnerApiInterceptor`（被启用时）读取，且白名单非空才真正收紧（见 `CInnerApiConfig.adoc` 5.1）。
- **`@Inherited` 仅对类级标注生效**：标在父类类级时子类自动继承；方法级标注不随方法继承传播，需标在具体方法上。
- `@Target` 仅 `TYPE`/`METHOD`：标注在字段、参数等其它位置不生效，编译器会报错。

=== 5.2 边界

- 仅作声明标记，无运行时自身行为；是否生效完全取决于消费方拦截器是否装配。

=== 5.3 波及影响

- 注解声明于 ctool4j-definition，可被 `CMpController`（mybatis-base）等引用；若将来扩充注解属性或语义，需同步评估对 web 拦截器及各使用方的影响。
