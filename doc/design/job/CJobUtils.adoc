= CJobUtils 设计文档

Version: 1.0
LastModified: 2026-08-21
模块：ctool4j-job-base
类：com.c332030.ctool4j.job.util.CJobUtils
状态：已落地
适用范围：定时任务按天划分执行时间窗口的工具

== 1. 功能说明

`CJobUtils`（`@UtilityClass`）提供定时任务的时间窗口计算：

- `dayJobTime(param, consumer)`：按参数时间计算当天的开始/结束时间窗口（`days=1`）。
- `dayJobTime(param, days, consumer)`：按参数时间向前覆盖 `days` 天计算时间窗口。

时间窗口语义：
- `endTime`：参数所在日的次日零点（按系统默认时区日边界截断）。
- `startTime`：`endTime` 向前减 1 小时再减 `days` 天。
- `consumer.accept(startTime, endTime)` 接收计算结果。

== 2. 设计要点

=== 2.1 时间计算

- param 非空时用 hutool `DateUtil.parse` 解析为 `Instant`；param 为空/空白时取当前时间 `Instant.now()`。
- `endTime = 参数时间所在日 次日零点`（`truncatedTo(DAYS)` 后 `plusDays(1)`）。
- `startTime = endTime - 1 小时 - days 天`（故意多减 1 小时，向前多覆盖 1 小时，避免任务执行延迟导致边界数据漏处理）。

=== 2.2 异常处理

- param 格式非法时抛异常（`DateUtil.parse`），交由任务框架处理，不静默兜底。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| param 为空/空白 | 取当前时间 `Instant.now()` 计算 |
| param 格式非法 | 抛出 `cn.hutool.core.date.DateException` |

== 4. 适用范围

=== 4.1 适用场景

- 每日/多日定时任务的执行时间窗口计算。

=== 4.2 不适用/边界场景

- 时区相关计算依赖系统默认时区，跨时区部署时结果可能不同。

== 5. 已知限制与取舍

- 时区按 `ZoneId.systemDefault()`，不显式指定。
- startTime 故意向前多减 1 小时作为时间窗口缓冲，属设计取舍。

测试内容见 `doc/design/job/CJobUtilsTests.adoc`。
