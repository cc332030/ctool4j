== 用例设计思路与依据

=== 设计思路

- 覆盖 apply 分支输出：required=true+value（必填+描述）、required=true 无 value（仅必填）、required=false（不标记必填）、未标注 @CSchema（不处理）。
- 覆盖 supports 支持性。

=== 设计依据

- 依据功能设计对"required=true 标记必填、value 非空写描述"的约定。
- 依据白盒/黑盒原则与分支覆盖：required 与 value 的组合、未标注场景均覆盖。

=== 覆盖场景与未覆盖

- 覆盖：required+value 组合、required 无 value、required=false、未标注、supports。
- 未覆盖：通过 getter 查找注解的路径、真实 springfox 文档生成链路。

== 1. apply 分支输出

- 1.1 required=true+value，必填+描述（apply_fieldRequiredWithValue）
- 1.2 required=true 不带 value，仅必填描述为空（apply_fieldRequiredWithoutValue）
- 1.3 required=false 不标记必填（apply_fieldNotRequired）
- 1.4 未标注 @CSchema 不处理（apply_unAnnotatedField）

== 2. supports

- 2.1 支持 SWAGGER_2/12（supports）
- 2.2 null 文档类型也支持（supports_null）
