= CLazyRef 测试用例文档

Version: 1.10
LastModified: 2026-09-10
所属功能：`com.c332030.ctool4j.core.util.CLazyRef`（core 模块）——懒加载值持有器。

对应测试类：`com.c332030.ctool4j.core.test.util.CLazyRefTests`

对应设计文档：`doc/design/core/CLazyRef.adoc`

== 用例设计思路与依据

=== 设计思路

- 纯逻辑单测，不依赖 Spring/外部服务。
- 用 `AtomicInteger` 计数 supplier 调用次数，验证"懒加载、只求值一次"。
- 用 `CountDownLatch` + 线程池制造并发，验证 DCL 线程安全。
- 用"静态初始化置位的探测类（Probe）"与"不存在的类名（Class.forName）"验证
  **构造 CLazyRef 不触发被引用类加载**（class not found 延迟到首次 get）。
- 用自定义 ClassLoader 屏蔽可选依赖类，验证两种环境（有依赖 / 无依赖）。

=== 设计依据

- 依据 CLazyRef 设计约定（懒加载、只求值一次、null 缓存、线程安全、类加载延迟）。
- 依据黑盒/白盒原则：正常路径、边界（null）、并发、类加载时序均需覆盖。

=== 覆盖场景与未覆盖

- 覆盖：懒加载、只求值一次、null 结果缓存、并发只求值一次、构造不初始化被引用类、被引用类缺失延迟到 get 抛错、
  of(null) 空值防御、lambda 与各类方法引用（静态/实例）均不抛异常、静态字段初始化、两种环境（有/无依赖）。
- 未覆盖：supplier 抛异常后的重试语义（设计已说明下次 get 重新求值，未单测）；
  "返回类型未擦除的 lambda"在无依赖环境于类初始化阶段报错（该限制由 1.14 以方法引用间接记录，
  未单独为该 lambda 写法建用例）。

== 1. CLazyRef 行为

- 1.1 构造时不求值，首次 get 才求值（get_lazy）
- 1.2 只求值一次，多次 get 返回同一实例（get_onlyOnce）
- 1.3 supplier 返回 null 也缓存，不重复求值（get_nullCached）
- 1.4 并发 get 只求值一次（get_concurrent_onlyOnce）
- 1.5 构造 CLazyRef 不触发被引用类初始化，首次 get 才初始化（of_shouldNotInitializeReferencedClass）
- 1.6 被引用类缺失（class not found）延迟到 get 才抛，构造不抛（of_missingClass_doesNotThrowAtConstruction）
- 1.7 静态方法引用作为 supplier（依赖已存在的正常路径）：构造与取值均不抛异常（of_staticMethodReference_noException）
- 1.8 lambda 表达式作为 supplier（依赖已存在的正常路径）：构造与取值均不抛异常（of_lambda_noException）
- 1.9 实例方法引用作为 supplier（依赖已存在的正常路径）：构造与取值均不抛异常（of_instanceMethodReference_noException）
- 1.10 静态字段初始化（静态方法初始化）：构造类不抛异常且懒加载（staticField_lazy_noException）
- 1.11 有依赖 + lambda（返回类型擦除 Object）：初始化不报错、取值不报错（withDep_lambda_initAndGet_noException）
- 1.12 有依赖 + 方法引用（具体类型）：初始化不报错、取值不报错（withDep_methodRef_initAndGet_noException）
- 1.13 无依赖 + lambda（返回类型擦除 Object）：初始化不报错、取值才报错（withoutDep_lambda_initOk_getThrows）
- 1.14 无依赖 + 方法引用：初始化即报错（withoutDep_methodRef_initThrows）——如实记录该限制
- 1.15 of(null) 抛异常（of_nullSupplier_throws）——如实记录 Lombok `@NonNull` 抛 `IllegalArgumentException`

> 注：
> * 1.7 / 1.8 刻意对比 lambda 与方法引用（均为"依赖已存在"的正常路径），局部 `@SuppressWarnings("all")`
>   抑制"可替换为方法引用"等无关告警以保留对比意图。
> * 1.11 与 1.13 使用同一 Holder（`CLazyLambdaDepHolder`，返回类型擦除为 Object），分别在"有依赖 / 无依赖"
>   两种环境验证；1.12 与 1.14 同用 `CLazyMethodRefDepHolder`（具体类型）。
> * 1.14 实际抛出 `BootstrapMethodError`（`invokedynamic` 引导失败），其 cause 为 `NoClassDefFoundError`，
>   断言精确匹配前者。
