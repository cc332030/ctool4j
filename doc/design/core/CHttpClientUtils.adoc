状态：已落地
适用范围：HTTP 客户端全局配置（超时、连接池、长连接、Spring 请求工厂）

== 1. 功能说明

`CHttpClientUtils` 为 HTTP 客户端配置工具类，提供全局可复用的 HttpClient 组件常量：

- 超时常量：`CONNECTION_REQUEST_TIMEOUT=3000`、`CONNECT_TIMEOUT=3000`、`SOCKET_TIMEOUT=30000`、
  `KEEP_ALIVE_TIMEOUT=10000`、`MAX_TOTAL_CONNECTIONS=1000`
- `REQUEST_CONFIG`：默认请求配置（含上述超时）
- `CONNECTION_MANAGER`：连接池管理器（最大连接数/单路由并发）
- `KEEP_ALIVE_STRATEGY`：长连接策略
- `HTTP_CLIENT`：全局 HTTP 客户端（禁用自动重试）
- `REQUEST_FACTORY`：Spring `ClientHttpRequestFactory`

== 2. 设计要点

=== 2.1 连接池

- `PoolingHttpClientConnectionManager` 设 `setMaxTotal(1000)` 与
  `setDefaultMaxPerRoute(1000)`（显式提升单路由并发，避免并发被路由级默认 2 限制）。

=== 2.2 长连接策略

- 基于 `DefaultConnectionKeepAliveStrategy.INSTANCE` 获取服务端建议时长，不足（<=0）时
  使用 `KEEP_ALIVE_TIMEOUT=10s` 兜底。

=== 2.3 客户端与工厂

- `HTTP_CLIENT` 禁用自动重试、设置默认请求配置、连接池与长连接策略。
- `REQUEST_FACTORY` 基于 HTTP_CLIENT 构建 Spring 请求工厂，供 Spring 模板使用。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 长连接服务端未给建议/建议不足 | 使用 KEEP_ALIVE_TIMEOUT=10s |

== 4. 适用范围

=== 4.1 适用场景

- Spring RestTemplate/WebClient 等需要统一超时与连接池的 HTTP 客户端配置。

=== 4.2 不适用/边界场景

- 常量配置全局共享，单业务特殊超时需另建客户端。
- 禁用自动重试，需要重试时自行配置。

== 5. 已知限制与取舍

- 全局单例 HttpClient，连接池共享，减少连接创建开销。
- 禁用自动重试，避免重试导致的重复请求副作用，由调用方决策是否重试。

测试内容见 `doc/design/core/CHttpClientUtilsTests.adoc`。
