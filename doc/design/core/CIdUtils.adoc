= CIdUtils 设计文档

Version: 1.4
LastModified: 2026-09-09
模块：ctool4j-core
类：com.c332030.ctool4j.core.util.CIdUtils
状态：已落地
适用范围：UUID / 雪花 ID / Nano ID / ULID 生成、类 ID 前缀计算、带前缀雪花 ID、ID 前缀解析

== 1. 功能说明

`CIdUtils` 为 ID 生成与解析工具类，提供：

- `UUID` / `simpleUUID`：生成带/不带 '-' 的 UUID 字符串（UUID v7，时间有序）——**可选能力**
- `nextId`：生成雪花 ID（Long）（core 强能力，基于 hutool）
- `nanoId` / `nanoId(size)`：生成 Nano ID 字符串（默认 21 字符，URL 安全字母表，无序）——**可选能力**
- `ulid`：生成 ULID 字符串（26 字符，Crockford Base32 大写，时间可排序）——**可选能力**
- `getPrefix(Class)` / `getPrefix(Class, length)`：计算类的 ID 前缀（优先 `@CBizId` 注解值，
  否则取类名大写字母去 `DO`）
- `nextIdWithPrefix`：生成带前缀（字符串/类前缀）的雪花 ID
- `getPrefixFromId`：从 ID 中解析前缀（数字前的字符）

=== 1.1 可选依赖说明（重要）

以下 ID 生成能力对应的实现库均为 **Maven `optional` 可选依赖**（默认**不会**传递给使用 ctool4j-core 的下游），
使用方用到对应方法时须在自己的 pom 显式引入：

- `UUID` / `simpleUUID`（UUID v7）依赖 `java-uuid-generator`
- `nanoId` / `nanoId(size)` 依赖 `jnanoid`
- `ulid` 依赖 `ulid-creator`

[source,xml]
----
<!-- 使用 CIdUtils.UUID/simpleUUID 时引入 -->
<dependency>
    <groupId>com.fasterxml.uuid</groupId>
    <artifactId>java-uuid-generator</artifactId>
</dependency>
<!-- 使用 CIdUtils.nanoId 时引入 -->
<dependency>
    <groupId>com.aventrix.jnanoid</groupId>
    <artifactId>jnanoid</artifactId>
</dependency>
<!-- 使用 CIdUtils.ulid 时引入 -->
<dependency>
    <groupId>com.github.f4b6a3</groupId>
    <artifactId>ulid-creator</artifactId>
</dependency>
----

若使用方未引入对应依赖却调用对应方法（如 `UUID`），运行时会抛 `NoClassDefFoundError`；
但 `nextId`（雪花 ID，依赖 hutool）、`getPrefix` 等强能力方法**不受影响**（生成器懒加载，类加载不依赖可选库）。
`nextId`（雪花 ID）依赖 hutool，为 core 强能力，无需单独引入。

== 2. 设计要点

=== 2.1 UUID 生成（UUID / simpleUUID）

- 使用 `com.fasterxml.uuid.Generators.timeBasedEpochGenerator()` 生成 **UUID v7**（时间有序），
  相比 v4 随机 UUID，索引友好、可排序，且无需维护状态即可保证全局唯一。
- 生成器以类级字段 `UUID_V7_GENERATOR` 懒加载缓存复用，双重检查锁样板由 `CLazyRef`（见
  `doc/design/core/CLazyRef.adoc`）统一封装，避免每次调用重复创建实例、也避免在工具类里散落 DCL 代码；
  仅在调用 `UUID`/`simpleUUID` 时才初始化，类加载不触发；该生成器本身**线程安全**
  （内部 `synchronized` 保护时间戳/熵状态），可安全并发共享。
- 字段声明为 `CLazyRef<TimeBasedEpochGenerator>` + lambda：`CLazyRef.of(() -> Generators.timeBasedEpochGenerator())`，
  `UUID()` 直接 `get()`。lambda（而非方法引用）使 `Generators` 延迟到首次 `get()` 才加载。
- 输出为带 '-' 的标准 UUID 字符串（36 位）；`simpleUUID` 在其基础上去除 '-'（32 位）。

=== 2.2 前缀计算规则（CLASS_PREFIX）

- 优先取 `@CBizId` 注解的 `value`（非空白时）。
- 无注解值回退取类简单名的所有大写字母并去除 `DO` 子串（如 `CIdUtilsTests` → `CIUT`）。
- 按类缓存（`CClassValue`，基于 `java.lang.ClassValue`，线程安全、按类弱关联），避免重复计算。

=== 2.3 前缀截取（getPrefix(Class, length)）

- 取 `prefix.substring(0, min(length, prefix.length()))`：length 超前缀长度时返回完整前缀。

=== 2.4 前缀解析（getPrefixFromId）

- 从 ID 开头扫描到第一个数字字符，取之前的字符为前缀；无前缀（ID 以数字开头或为空）返回 null。

=== 2.5 Nano ID 生成（nanoId / nanoId(size)）

- 复用**开源 jnanoid**（`com.aventrix.jnanoid:jnanoid`）的 `NanoIdUtils`：
  - `randomNanoId()`：默认 21 字符、URL 安全字母表 `A-Za-z0-9_-`、`SecureRandom`。
  - `randomNanoId(Random, char[], int)`：自定义随机源/字母表/长度，nanoId(size) 用默认 SecureRandom 与默认字母表。
- 相比 UUID（36 位）更短、URL 友好、无序；适合需要较短但唯一性足够（21 字符）的场景。
- `SecureRandom`（`NanoIdUtils.DEFAULT_NUMBER_GENERATOR`）线程安全，可并发共享。
- 依赖为可选（optional），见 1.1。

=== 2.6 ULID 生成（ulid）

- 复用**开源 ulid-creator**（`com.github.f4b6a3:ulid-creator`）的 `UlidCreator.getMonotonicUlid()`（标准加密 ULID）。
- 格式：26 字符、大写 Crockford Base32（`0-9A-HJKMNP-TV-Z`，不含 `I/L/O/U`），128 位 = 48 位毫秒时间戳 + 80 位随机。
- 特性：字符串字典序即生成时间序（可排序）、**同一毫秒内单调递增**（严格保证排序）、前 10 字符时间戳可解码回毫秒、短于 UUID。
  - 选用 `getMonotonicUlid()` 而非 `getUlid()`：后者同一毫秒内随机后缀不保证递增（同毫秒并发生成可能乱序），
    与"时间可排序"的设计意图不符；monotonic 版确保时间戳相同后缀递增，真正满足可排序。
- 相比 Nano ID：同为 URL 友好但**时间可排序**；适合需"短 + 可排序"的 ID。
- 依赖为可选（optional），见 1.1。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| getPrefixFromId 空 ID/null | 返回 null |
| getPrefixFromId 无前缀（ID 以数字开头） | 返回 null |
| getPrefixFromId(String, convert) 无前缀 | 返回 null，不调用 convert |

== 4. 适用范围

=== 4.1 适用场景

- 需要 UUID / 雪花 ID / Nano ID 作为主键/业务 ID。
- 需要按类生成带稳定前缀的雪花 ID（`@CBizId` 注解或类名约定）。
- 需要较短、URL 友好、无序的 ID（Nano ID）。
- 需要较短、URL 友好、时间可排序的 ID（ULID）。

=== 4.2 不适用/边界场景

- 前缀解析只识别"数字前的字符"；ID 中后续数字不影响前缀解析。
- getPrefix 按类缓存，运行期类上加/改 `@CBizId` 注解不会刷新（转换器静态注册，无动态需求）。

== 5. 已知限制与取舍

- 前缀缓存无失效机制：`@CBizId` 注解理论上静态不可变，风险低（沿用 CClassValue 约定）。
- `getPrefixFromId` 语义简单（数字前字符），不做复杂的前缀分隔规则。
- Nano ID 依赖 jnanoid（`com.aventrix.jnanoid:jnanoid` 2.0.0，MIT，零传递依赖）：该库为社区事实标准 Java nanoid 实现、多年稳定（版本未再更新），算法简单可靠；Nano ID 无序、不含时间信息，不适合需要排序/可追溯的 ID。
- ULID 依赖 ulid-creator（`com.github.f4b6a3:ulid-creator` 5.2.4，MIT，Java 8）。
- `UUID`/`simpleUUID`、`nanoId`、`ulid` 为**可选能力**：若使用方未引入对应依赖却调用对应方法，会抛 `NoClassDefFoundError`（见 1.1）；未调用对应方法时不影响 `nextId`/`getPrefix` 等强能力（生成器懒加载）。判断 ID 是否需要可排序时选型：UUID v7/雪花（时间有序）、Nano ID（短无序）、ULID（短时间有序）。

测试内容见 `doc/design/core/CIdUtilsTests.adoc`。

== 变更日志

- 1.9 | 2026-09-10 | UUID v7 生成器懒加载由内联双重检查锁改为复用 `CLazyRef`（`CLazyRef.of(() -> ...)`），消除工具类内 DCL 样板；lambda（非方法引用）确保 `Generators` 延迟到首次 get 才加载。原 DCL 以 `null == uuidV7Generator` 判定（生成器为 null 时每次都重新求值），改用 `CLazyRef` 后以 `initialized` 标志判定，**缓存 null 结果**（生成器不会返回 null，实际行为等价，语义更标准）
- 1.4 | 2026-09-09 | ULID 改用 `getMonotonicUlid()`：确保同一毫秒内单调递增、严格可排序（原 `getUlid()` 同毫秒随机后缀可能乱序，与"时间可排序"设计意图不符），修复 ulid_timeOrdered 用例偶发失败
- 1.3 | 2026-09-09 | UUID v7 生成器改为懒加载（双重检查锁）：消除类加载对可选依赖 java-uuid-generator 的强制依赖，未引入该依赖时 nextId/getPrefix 等强能力方法不再受影响（修复 NoClassDefFoundError）
