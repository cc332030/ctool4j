== 性能测试设计思路

=== 被测对象

简单 el 属性链表达式取值，代表性场景：

- 深链（多级属性跳）：`person.contact.address.code`，验证多级 MethodHandle getter 链。
- 一级（仅参数名）：`user`，验证无属性跳的最快路径（零分配直接返回参数对象）。

=== 对比维度（≥3 类实现，实现原理各不相同）

- `CElKeyResolveUtils`（被测）：表达式一次解析按方法缓存 + getter 按类缓存 MethodHandle。
- 原生反射：每次调用逐级 `getDeclaredField + Field.get`，无任何缓存（最朴素实现）。
- hutool `BeanUtil.getProperty`：反射实现，内部有缓存。
- 编译期直接赋值（基线）：手工 getter 链。

=== 执行方式

- 性能测试独立于单元测试，仅在明确命令执行时才运行（`mvn test -Dtest=CElKeyResolveUtilsBenchmarkTests`）。
- 排除初始化干扰：先对所有用例做一轮全局预热，触发全部实现方式初始化/加载，首次结果不计入。
- 充分预热 + 足够迭代：预热 50 万次触发 JIT 至 C2 稳态，单轮计时 100 万次、取 5 轮平均，降低测量噪声。
- 结果写入 `tmp/benchmark-report-celkeyresolver.md` 报告，分析性能差异原因并给出方案。
