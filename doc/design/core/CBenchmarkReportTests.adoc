= CBenchmarkReport 测试用例文档

Version: 1.0
LastModified: 2026-08-21
所属功能：`com.c332030.ctool4j.core.benchmark.CBenchmarkReport`（core benchmark 包）——性能基准报告，含标题与按耗时升序的结果列表（首项为基线），支持导出 markdown 表格与写文件。

对应测试类：`com.c332030.ctool4j.core.test.benchmark.CBenchmarkReportTests`

对应设计文档：`doc/design/core/CBenchmarkReport.adoc`（功能设计，测试内容以本文档为准）。

本文档为 CBenchmarkReport 的测试用例文档，含用例设计思路与依据、覆盖场景，以及测试用例的分类编号索引；测试方法在 javadoc 中标注对应编号（如 `对应测试用例 2.1`），文档与代码互相定位，便于检查覆盖是否有遗漏。

== 用例设计思路与依据

=== 设计思路

- 白盒分析：`toMarkdown()` 遍历结果列表，取首项为基线计算"相对基线"（`avgNanos / baseline`）；
  `writeTo(Path)` 先创建父目录再以 UTF-8 写出，IO 异常包装为 `RuntimeException`。需覆盖
  多结果表格、单结果（相对基线 1.00x）、空列表（`results.get(0)` 抛
  `IndexOutOfBoundsException`）、文件写入成功与失败分支。
- 黑盒分析：入参为标题与结果列表，出参为 markdown 字符串与写入的文件；取值覆盖
  典型多结果、单结果、空列表（异常）、相对路径父目录创建。
- 错误推测法：空列表调用 `toMarkdown`/`writeTo` 会在 `results.get(0)` 处抛
  `IndexOutOfBoundsException`；`writeTo` 对无父目录的简单路径不创建目录；写入失败（如
  目标路径为已存在目录）抛 `RuntimeException`。

=== 覆盖场景

- 覆盖：`getTitle`/`getResults` 正例；`toMarkdown` 多结果表格列完整、单结果基线为 1.00x、
  空列表异常；`writeTo` 写入成功（含自动创建父目录）、UTF-8 编码、目标为目录时抛
  `RuntimeException`。
- 未覆盖：`String.format` 的 locale 差异（CI 与本地均按默认 locale 运行，非跨 locale 场景）。

== 1. 字段取值（getTitle / getResults）

- 1.1 正例：构造后 `getTitle` / `getResults` 原样返回构造入参

== 2. toMarkdown()

- 2.1 正例：多结果，表格含「实现方式 / Avg(ns/op) / ops/s / 相对基线」各列，相对基线以首项为基线
- 2.2 边界：单结果，相对基线为 1.00x
- 2.3 异常：空结果列表 → 抛 IndexOutOfBoundsException

== 3. writeTo(Path)

- 3.1 正例：写入临时文件成功，内容与 `toMarkdown()` 一致，父目录自动创建
- 3.2 边界：无父目录的相对路径也可写入成功
- 3.3 异常：目标路径为已存在目录 → 抛 RuntimeException（IO 失败）
