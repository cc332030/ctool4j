= CCollectors 设计文档

Version: 1.0
LastModified: 2026-08-21
模块：ctool4j-core
类：com.c332030.ctool4j.core.util.CCollectors
状态：已落地
适用范围：Stream 收集为不可变 List/Set/LinkedHashMap、有序 Set 等

== 1. 功能说明

`CCollectors` 为 Stream 收集器工具类，提供：

- `toUnmodifiableList`：收集为不可变 List
- `toUnmodifiableLinkedMap`：收集为不可变 LinkedHashMap（多个重载：仅键 / 键+冲突合并 / 键值 / 键值+冲突合并）
- `toLinkedSet`：收集为 LinkedHashSet（保持插入顺序）
- `toUnmodifiableSet`：收集为不可变 Set

== 2. 设计要点

=== 2.1 不可变收集语义

- `toUnmodifiableList` / `toUnmodifiableSet` / `toUnmodifiableLinkedMap` 通过
  `Collectors.collectingAndThen(..., Collections::unmodifiableXxx)` 收集后再包一层不可变视图，
  调用方后续 `add/put` 抛 `UnsupportedOperationException`。
- `toLinkedSet` 收集为 `LinkedHashSet`（可变，保持插入顺序）。

=== 2.2 LinkedHashMap 键冲突约定

- 未显式提供 mergeFunction 的重载，键冲突时默认抛 `IllegalStateException`（"Conflict key, ..."）。
- 显式传入 mergeFunction 的重载，键冲突时按合并函数处理。

=== 2.3 键值提取

- 仅键的重载值使用 `Function.identity()`（元素自身为值）。
- 键值重载分别通过 keyMapper/valueMapper 提取。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 收集后调用 add/put | 抛 UnsupportedOperationException（不可变） |
| LinkedMap 键冲突（未提供 merge） | 抛 IllegalStateException（"Conflict key, ..."） |
| LinkedMap 键冲突（提供 merge） | 按 mergeFunction 合并 |

== 4. 适用范围

=== 4.1 适用场景

- Stream 结果需要不可变集合，避免外部误改。
- 需要保持插入顺序的 Map（LinkedHashMap）或 Set（LinkedHashSet）。

=== 4.2 不适用/边界场景

- 键冲突默认抛异常，未显式提供 merge 时对重复键数据不友好；有重复键需传 mergeFunction。
- toUnmodifiableSet 基于 `Collectors.toSet()`（HashMap），元素顺序不保证。

== 5. 已知限制与取舍

- 不可变收集为视图而非深拷贝；原集合被并发修改时行为未定义（与 JDK 收集器一致）。
- 默认键冲突抛异常，强制调用方显式决策重复键策略，避免静默丢数据。

测试内容见 `doc/design/core/CCollectorsTests.adoc`。
