== 用例设计思路与依据

=== 设计思路

- 按「仅错误码 / 错误码+附加 / 错误码+原因 / 全参数 / null 错误码」多个构造覆盖。
- 用 `TestRes`（实现 ICRes）提供 code/msg，验证消息格式化 `[code] msg[: detail]`。

=== 设计依据

- 依据功能设计对消息格式化（formatResMessage）与字段设置的约定。

=== 覆盖场景与未覆盖

- 覆盖：errorOnly、error+msgExtend、error+cause、error+msgExtend+cause、null error。
- 未覆盖：无（覆盖了全部构造）。

== 1. 构造

- 1.1 仅错误码：`[100] boom`，error 正确、msgExtend null（errorOnly）
- 1.2 错误码+附加：`[100] boom: detail`，msgExtend 正确（errorAndMsgExtend）
- 1.3 错误码+原因：`[100] boom`，cause 正确（errorAndCause）
- 1.4 全参数：`[100] boom: detail`，cause 与 msgExtend 正确（errorMsgExtendCause）
- 1.5 null 错误码：消息仅含 `only-extend`，error null（nullError）
