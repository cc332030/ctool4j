== 用例设计思路与依据

=== 设计思路

- 按「创建业务异常 / 异常链信息」两个维度组织。
- 创建验证默认提供者返回 CBusinessException。
- 异常链覆盖 null（返回 null，Q17）与含 cause 的拼接展示。

=== 设计依据

- 依据功能设计对默认提供者类型与异常链拼接的约定。

=== 覆盖场景与未覆盖

- 覆盖：newBusinessException 返回 CBusinessException；getMessageWithCause null 返回 null；含 cause 拼接。
- 未覆盖：`ignore`/`throwBusinessException`/SPI 自定义提供者（当前测试聚焦创建与异常链核心路径，
  其余入口可后续批次补充）。

== 1. 创建业务异常

- 1.1 newBusinessException：返回 CBusinessException（newBusinessException）

== 2. 异常链信息

- 2.1 null 异常：返回 null（getMessageWithCauseNull，Q17）
- 2.2 含 cause：消息含 main 与 cause（getMessageWithCause）
