== 用例设计思路与依据

=== 设计思路

- 按「formatMessage / formatResMessage」两个方法、各覆盖「正例 / res null / 扩展信息为空」三类场景。
- 用匿名实现 `ICRes<String>` 模拟响应对象（getCode/getMsg），贴近真实使用。

=== 设计依据

- 依据功能设计对空值语义的约定（res null 返回扩展信息、扩展空返回 msg）。
- 依据测试方法（等价类/边界值）：正例、res null、扩展信息空/空白。

=== 覆盖场景与未覆盖

- 覆盖：两方法的正例（含扩展信息）、res null、msgExtend 为 "" / null。
- 未覆盖：无（覆盖了全部入口与空值分支）。

== 1. formatMessage

- 1.1 正例：`res("ok")` → `"ok"`；带扩展 `"ok: extra"`（formatMessage）
- 1.2 res null：返回 null / 返回 `"extra"`（formatMessageNullRes）
- 1.3 扩展为空：`""` / null 均返回 `"ok"`（formatMessageEmptyExtend）

== 2. formatResMessage

- 2.1 正例：`[200] ok`；带扩展 `[200] ok: extra`（formatResMessage）
- 2.2 res null：返回 null / 返回 `"extra"`（formatResMessageNullRes）
- 2.3 扩展为空：`""` / null 均返回 `[200] ok`（formatResMessageEmptyExtend）
