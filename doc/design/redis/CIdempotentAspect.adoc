= CIdempotentAspect 设计文档

Version: 1.1
LastModified: 2026-09-09
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.idempotent.CIdempotentAspect
状态：已落地
适用范围：@CIdempotent 方法的幂等切面（基于 Redis 分布式锁）

== 1. 功能说明

`CIdempotentAspect`（`@Aspect` + `@Component`）拦截标注 `@CIdempotent` 的方法，
基于 `CLockService` 分布式锁实现同一业务 key 的互斥执行，加锁失败抛幂等异常。

== 2. 设计要点

=== 2.1 幂等 key

- 格式：`应用前缀:分组类简单名:方法名:业务id`（业务 id 为空时省略最后一段）。
- 应用前缀取自 `CRedisUtils.getApplicationPrefix()`（优先 group，其次 name）。
- 分组类简单名取自注解 `group()`（而非方法声明类），支持多方法共用同一分组。
- 注解 `useMethodName()` 为 false 时省略方法名段，同组多个方法共享同一执行权。
- 业务 id 由公共工具 `CRedisKeyUtils.resolveBizId`（内部走 `CElKeyResolveUtils`）按 `id()` 表达式取值，区分调用维度；key 构建复用 `CRedisKeyUtils.buildKey`。

=== 2.2 执行权获取（复用 CLockService）

- 复用 `CLockService.lock(key).onLockFail(抛异常).execute(业务)` 模板。
- 加锁成功 → 锁内执行业务（`CAspectUtils.process`）→ 释放锁。
- 加锁失败（同一 key 已有调用）→ 执行 `onLockFail` 回调抛 `CIdempotentException`。
- 默认 `waitTime=ZERO` 不等待，并发立即可感知拒绝。

=== 2.3 业务 id 解析

- 复用 `CRedisKeyUtils.resolveBizId`（内部走 `CElKeyResolveUtils`）解析注解 `id()` 表达式，从方法参数取业务维度值。
- 表达式为空或求值为 null/空白时，幂等不带业务维度（按分组类+方法名全局隔离）。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| id 表达式非法 | 抛 IllegalArgumentException（CElKeyResolveUtils，经 CRedisKeyUtils） |
| id 求值为 null | 按分组类+方法名全局隔离 |
| 加锁失败（重复/并发） | 抛 CIdempotentException |
| 锁内业务异常 | 传播业务异常（CLockService finally 释放锁） |
| Redis 异常 | 向上抛出（不静默降级放行，由调用方决定故障策略） |

== 4. 适用范围与取舍

- 切面作为 Spring Bean 由组件扫描自动注册，需消费方组件扫描到 `com.c332030.ctool4j.redis.idempotent` 包。
- 通过 `CLockService` 注入（构造器注入），依赖 `RedissonClient`。
- 幂等只在持锁期间生效；方法完成后锁释放，后续新请求可再次执行（如需「完成后不可重放」需另做持久标记）。

测试内容见 `doc/design/redis/CIdempotentAspectTests.adoc`。
