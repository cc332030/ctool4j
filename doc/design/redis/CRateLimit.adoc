= CRateLimit 设计文档

Version: 1.1
LastModified: 2026-09-09
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.rate.CRateLimit
状态：已落地
适用范围：基于 Redis 固定窗口的限流注解，作用于方法

== 1. 功能说明

`@CRateLimit` 为方法级限流注解，由 `CRateLimitAspect` 切面拦截。在 `interval` 秒窗口内，
允许 `count` 次调用；超过阈值抛 `CRateLimitException`。

== 2. 注解属性

| 属性 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `id()` | String | `""` | 业务 id 简单 el 表达式，空表示不按业务维度限流 |
| `count()` | int | 无 | 窗口内允许的最大调用次数，必须 > 0 |
| `interval()` | long | 无 | 时间窗口大小（秒），必须 > 0 |
| `useMethodName()` | boolean | `true` | 是否将方法名纳入限流 key；false 时同类多方法共享同一限流桶 |
| `message()` | String | 请求过于频繁，请稍后再试 | 限流时抛出的异常消息 |

=== 2.1 id() 表达式

- 格式 `参数名.属性名.属性名…`，参考 `@CCacheable.key()`。
- 由公共解析器 `CElKeyResolveUtils` 求值，从方法参数取业务维度值。
- 为空或求值为 null 时，限流不带业务维度（按方法全局限流）。

=== 2.2 useMethodName() 方法名隔离

- 默认 `true`：key 含 `类简单名:方法名`，各方法按自身隔离。
- 设为 `false`：key 去掉方法名段（`应用前缀:类简单名:业务id`），同类的多个方法共享同一限流桶。
- 用途：同一业务的多个入口/共用一个限流维度时，避免各方法独立计数导致总频率失控。

=== 2.3 CRateLimitException

继承 `CException`（运行时异常）。限流触发时抛出，携带 `message()` 指定的消息。

== 3. 设计要点

- 固定窗口计数器（INCR + 首次 EXPIRE 原子脚本，见 `CRedisUtils.incrExpire`），实现简单、原子。
- 业务 id 用于区分不同调用主体（如用户/商户/IP），使限流维度更精确。
- 参数校验：count/interval 必须为正，非法时切面抛 `IllegalArgumentException`。

== 4. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| count <= 0 | 切面抛 IllegalArgumentException |
| interval <= 0 | 切面抛 IllegalArgumentException |
| id 表达式非法/循环引用 | 切面抛 IllegalArgumentException/IllegalStateException（由 CElKeyResolveUtils 抛） |
| id 求值为 null | 按方法全局限流 |
| 窗口内超阈值 | 抛 CRateLimitException |

== 5. 适用范围与取舍

=== 5.1 适用场景

- 接口限流（按用户/IP/商户等维度）。
- 高频操作的频率控制。

=== 5.2 已知限制与取舍

- 固定窗口计数器在窗口临界点存在"窗口翻转瞬间突增"的边界问题（窗口初重置时刻允许冲过阈值一次）。
- 若需更平滑的限流（令牌桶/滑动窗口）需另行实现；本实现聚焦简单可靠的固定窗口计数。
- 计数依赖 Redis 可用性：Redis 异常时限流判定会抛出异常（非降级放行），调用方需自行处理 Redis 故障策略。
