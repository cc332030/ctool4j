= CRedisUtils 设计文档

Version: 1.0
LastModified: 2026-08-21
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.util.CRedisUtils
状态：已落地
适用范围：Redis key 生成与原子操作工具（含 Lua 脚本）

== 1. 功能说明

`CRedisUtils`（`@UtilityClass` + `@CAutowiredScan`）提供 Redis 工具能力：

- key 生成：应用前缀 + 类名 + key 段拼接（`getKey`/`getApplicationPrefix`）。
- 原子操作（Lua 脚本）：`setIfLager`、`compareAndSet`、`setIfNotEquals`、`setIfAbsent`。
- 一次性操作：`tryDoOnce`。
- 自增与业务 id：`incr`/`incrExpire`、`getIncrBizId`/`getDateIncrBizId`/`getDateTimeIncrBizId`。

== 2. 设计要点

=== 2.1 原子操作（Lua 脚本）

- `setIfLager`：仅当新值大于当前值时设置（默认当前值为 0）。
- `compareAndSet`：当前值等于期望值时才更新（按字符串比较，可带 TTL）。
- `setIfNotEquals`：当前值不等于新值时才设置（可带 TTL）。
- `setIfAbsent`：key 不存在时设置。

=== 2.2 key 生成语义

- `KEY_SEPARATOR = ":"`；`getApplicationPrefix` 优先分组、其次应用名。
- `getKey(clazz, keys...)` = `应用前缀:类简单名:key段...`。
- `getIncrBizId` 用 `"{}:biz_id:incr:{}"` 格式的递增 key，左补 0 到指定长度。

=== 2.3 实现方式

- Lua 脚本通过 `DefaultRedisScript` 执行，保证原子性。
- `compareAndSet`/`setIfNotEquals` 用字符串序列化模板执行，避免对象模板（JSON 引号）与字符串字节不一致导致比较恒失败。
- `setIfNotEquals` 脚本按 `ARGV[1]`=新值（比较）、`ARGV[2]`=新值（写入）、`ARGV[3]`=TTL 传参，保证写入的是新值而非 TTL。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| `setIfLager`/`compareAndSet`/`setIfNotEquals` 入参 null | 返回 false 不执行 |
| `tryDoOnce` 执行异常 | 删除 key（回滚占用）后重新抛出异常 |
| 应用前缀为空 | 退而取应用名 |

== 4. 适用范围

=== 4.1 适用场景

- 需要原子读-比较-写、去重/限流（tryDoOnce）、自增业务 id 的 Redis 场景。

=== 4.2 不适用/边界场景

- `compareAndSet`/`setIfNotEquals` 期望值/新值与存储值需由字符串序列化模板写入，否则比较结果不受保证。
- Lua 脚本依赖 Redis 服务器支持。

== 5. 已知限制与取舍

- `compareAndSet` 按字符串比较，存储字节序列化方式必须一致。
- 业务 id 自增依赖 Redis 单键原子性，跨实例由 Redis 保证。

测试内容见 `doc/design/redis/CRedisUtilsTests.adoc`。
