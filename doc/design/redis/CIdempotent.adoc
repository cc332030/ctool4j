= CIdempotent 设计文档

Version: 1.0
LastModified: 2026-09-09
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.idempotent.CIdempotent
状态：已落地
适用范围：基于 Redis 分布式锁的幂等/防并发注解，作用于方法

== 1. 功能说明

`@CIdempotent` 为方法级幂等注解，由 `CIdempotentAspect` 切面拦截。同一业务 key 在任一时刻
只能有一个调用执行业务，其余并发或重复调用抛 `CIdempotentException`，防止重复提交与并发穿透。

== 2. 注解属性

| 属性 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `id()` | String | `""` | 业务 id 简单 el 表达式，空表示不按业务维度隔离 |
| `group()` | Class<?> | 无（必填） | 分组类实例，其简单名作为 key 的类段 |
| `useMethodName()` | boolean | `true` | 是否将方法名纳入幂等 key；false 时同组多方法共享同一执行权 |
| `message()` | String | 重复请求，请勿重复提交 | 幂等冲突时抛出的异常消息 |

=== 2.1 id() 表达式

- 格式 `参数名.属性名.属性名…`，参考 `@CCacheable.key()`。
- 由公共解析器 `CElKeyResolveUtils` 求值，从方法参数取业务维度值。
- 为空或求值为 null 时，幂等不带业务维度（按分组类+方法名全局隔离）。

=== 2.2 group() 分组类

- 必填。取 `group()` 的简单名作为幂等 key 的类段，而非方法声明类的简单名。
- 这样可让多个方法（甚至跨类）通过指定相同分组类共享同一幂等维度。
- 配合 `useMethodName()` 关闭方法名段，即可让多个方法共享同一执行权。

=== 2.3 useMethodName() 方法名隔离

- 默认 `true`：key 含 `分组类简单名:方法名`，各方法按自身隔离。
- 设为 `false`：key 去掉方法名段（`应用前缀:分组类简单名:业务id`），同组多个方法共享同一执行权。
- 用途：同一业务的多个入口/共用一个幂等维度时，避免各方法独立、无法拦截跨方法的重复提交。

=== 2.4 CIdempotentException

继承 `CException`（运行时异常）。幂等冲突（获取执行权失败）时抛出，携带 `message()` 指定的消息。

== 3. 设计要点

- 复用 `CLockService`（Redisson 分布式锁）实现互斥：加锁成功 → 锁内执行业务 → 释放锁；
  加锁失败（同一 key 已有调用）→ 抛幂等异常。
- 业务 id 用于区分不同调用主体（如用户/商户），使幂等维度更精确。
- 默认不等待锁，并发立即可感知拒绝（防重复提交场景）。

== 4. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| id 表达式非法/循环引用 | 抛 IllegalArgumentException/IllegalStateException（由 CElKeyResolveUtils 抛） |
| id 求值为 null | 按分组类+方法名全局隔离 |
| 加锁失败（重复/并发） | 抛 CIdempotentException |

== 5. 适用范围与取舍

=== 5.1 适用场景

- 接口防重复提交（用户短时间重复点击、重复提交表单）。
- 防并发穿透（同一业务 key 同一时刻仅允许一个执行）。

=== 5.2 已知限制与取舍

- 幂等只在持锁期间（方法执行期间）生效：方法完成后锁释放，后续新请求可再次获取执行权。
  若需「完成后不可重放」需另做持久标记，超出本注解职责。
- 默认不等待锁，加锁失败立即抛异常；若需排队等待可在 `CLockService` 配置 `waitTime`，
  但本切面当前固定不等待。
- 计数/锁完全依赖 Redis 可用性：Redis 异常时幂等判定会抛出异常（非静默放行），调用方需自行处理。
- 同名重载方法若不指定 `useMethodName=false` 会共享同一执行权；需区分时依赖业务 id 体现差异。
