= CLockService 设计文档

Version: 1.0
LastModified: 2026-08-21
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.service.impl.CLockService
状态：已落地
适用范围：基于 Redisson 的分布式锁（加锁-执行-解锁统一模板）

== 1. 功能说明

`CLockService` 封装 Redisson 分布式锁，提供：

- `getLock(key)`：获取指定 key 的 `RLock`。
- `lock(lockKey)` / `lock(format, args...)`：创建 `CLockBuilder`（支持格式化 key）。
- `tryLock(...)` 系列：尝试加锁。
- `tryLockThenRun(...)`（已废弃）：获取锁并执行操作。

内部 `CLockBuilder` 提供链式配置（waitTime / leaseTime / onLockFail / unlockDelay），
统一"加锁-执行-解锁"模板。

== 2. 设计要点

=== 2.1 CLockBuilder 语义

- `waitTime`：等待获取锁超时，默认不等待（`Duration.ZERO`）。
- `leaseTime`：持锁时间，默认 `-1` 启用 Redisson watchdog 自动续期。
- `onLockFail`：获取锁失败回调，默认空操作（不抛异常）。
- `unlockDelay`：释放锁前延迟（默认不延迟），用于写缓存后延迟释放避免瞬间读到旧数据。

=== 2.2 加锁-执行-解锁模板

- `execute(Runnable)`：无返回值；`execute(Supplier)`：有返回值。
- 获取锁失败时执行 `onLockFail` 回调并返回 null（或 void）。
- `unlockSafely`：仅当前线程持有锁时释放；有 unlockDelay 先 sleep 再释放；释放异常仅记录日志。

=== 2.3 实现方式

- 基于 `RedissonClient`；`tryLockWithLeaseTime` 按 waitTime 是否有毫秒选择 `tryLock(millis, leaseTime, unit)` 或秒版本。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| 获取锁失败 | 执行 onLockFail 回调，返回 null（回调决定是否抛异常，默认不抛） |
| 加锁被中断 | 恢复中断标记，记录 error，视为获取失败 |
| 释放锁异常 | 记录 error 日志，不抛出 |
| 延迟释放被中断 | 恢复中断标记，记录 info |

== 4. 适用范围

=== 4.1 适用场景

- 需要分布式锁的读-算-写、缓存刷新、幂等控制等场景。

=== 4.2 不适用/边界场景

- 依赖 Redisson 客户端与 Redis 服务器；单机环境不适用。
- `tryLockThenRun` 已废弃，新代码使用 `lock()` 构建器。

== 5. 已知限制与取舍

- 默认 leaseTime=-1 依赖 watchdog 自动续期，若 Redis/Redisson 配置不支持续期，锁可能在长任务中过期。
- `unlockDelay` 期间锁仍被当前线程持有，其他线程获取会失败/等待，需谨慎配置。
