== 用例设计思路与依据

=== 设计思路

- 仅测试纯逻辑方法 `getLockKey(String)`，不依赖 Spring 容器与 Redis 连接。
- 覆盖普通 key、含冒号 key、空 key、含特殊字符 key。

=== 设计依据

- 依据功能设计对 `getLockKey(key)` 返回 `key + ":" + "lock"` 的约定。
- 依据白盒/黑盒原则：取普通、含分隔符、空、特殊字符代表性输入。

=== 覆盖场景与未覆盖

- 覆盖：普通、含冒号、空、特殊字符。
- 未覆盖：`lock()`/`tryLockThenRun`（依赖注入与 Redis，未单测）。

== 1. getLockKey 锁 key 生成

- 1.1 普通 key：`biz` → `biz:lock`（testGetLockKey_normal）
- 1.2 含冒号 key：`a:b` → `a:b:lock`（testGetLockKey_withColon）
- 1.3 空 key：`""` → `:lock`（testGetLockKey_empty）
- 1.4 含特殊字符：`key:1` → `key:1:lock`（testGetLockKey_specialChars）
