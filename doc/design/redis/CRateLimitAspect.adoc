= CRateLimitAspect 设计文档

Version: 1.2
LastModified: 2026-09-09
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.rate.CRateLimitAspect
状态：已落地
适用范围：@CRateLimit 方法的限流切面（基于 Redis 固定窗口计数器）

== 1. 功能说明

`CRateLimitAspect`（`@Aspect` + `@Component`）拦截标注 `@CRateLimit` 的方法，
在 Redis 中按 key 原子计数，根据计数与阈值决定放行或抛限流异常。

== 2. 设计要点

=== 2.1 限流 key

- 格式：`应用前缀:类简单名:方法名:业务id`（业务 id 为空时省略最后一段）。
- 应用前缀取自 `CRedisUtils.getApplicationPrefix()`（优先 group，其次 name）。
- 类简单名/方法名标识被限流的方法，避免不同方法相互影响；注解 `useMethodName()` 为 false 时省略方法名段，
  同类的多个方法共用同一限流桶。
- 业务 id 由公共工具 `CRedisKeyUtils.resolveBizId`（内部走 `CElKeyResolveUtils`）按 `id()` 表达式取值，区分调用维度；key 构建复用 `CRedisKeyUtils.buildKey`。

=== 2.2 计数（固定窗口）

- 复用 `CRedisUtils.incrExpire(key, 1, Duration.ofSeconds(interval))`：
  Lua 脚本原子 `INCRBY 1`，首次自增时设置 `EXPIRE interval`。
- 返回自增值 `current`；`current > count` 时判定超阈值。
- 边界：`current == count` 允许（第 count 次调用放行），第 count+1 次才拦截。

=== 2.3 参数校验

- `count <= 0` 或 `interval <= 0` 时抛 `IllegalArgumentException`，避免误配导致限流失效。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| count <= 0 | 抛 IllegalArgumentException |
| interval <= 0 | 抛 IllegalArgumentException |
| id 表达式非法 | 抛 IllegalArgumentException（CElKeyResolveUtils，经 CRedisKeyUtils） |
| 超阈值 | 抛 CRateLimitException |
| Redis 异常 | 向上抛出（不静默降级放行，由调用方决定故障策略） |

== 4. 适用范围与取舍

- 切面作为 Spring Bean 由组件扫描自动注册，需消费方组件扫描到 `com.c332030.ctool4j.redis.rate` 包。
- 计数完全依赖 Redis，多实例共享同一计数器，天然支持分布式限流。
- 同名重载方法共用同一限流 key（类名:方法名），若需区分需在业务 id 中体现方法差异。

测试内容见 `doc/design/redis/CRateLimitAspectTests.adoc`。
