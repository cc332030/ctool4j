= CLockUtils 设计文档

Version: 1.0
LastModified: 2026-08-21
模块：ctool4j-redis
类：com.c332030.ctool4j.redis.util.CLockUtils
状态：已落地
适用范围：分布式锁 key 生成与锁操作静态入口

== 1. 功能说明

`CLockUtils`（`@UtilityClass` + `@CAutowiredScan`）为分布式锁的静态访问入口，持有 `CLockService`（注入），提供：

- `getLockKey(...)`：生成锁 key（`业务key + ":" + "lock"`；或基于类/操作/key 组合）。
- `tryLockThenRun(...)`（已废弃）：获取锁并执行操作。
- `lock(...)`：创建锁构建器（支持格式化 key）。

== 2. 设计要点

=== 2.1 语义约定

- `getLockKey(key)` 返回 `key + ":" + "lock"`。
- `getLockKey(clazz, icOperate, key)` 先经 `CRedisUtils.getKey` 拼接应用前缀+类名+key，再加 lock 后缀。
- 通过 `@CAutowiredScan`/`@CAutowired` 注入 `CLockService`。

=== 2.2 实现方式

- 静态转发到 `CLockService`；`tryLockThenRun` 系列已废弃，推荐 `lock()` 构建器。

== 3. 兜底设计

| 场景 | 兜底行为 |
|------|---------|
| `lockService` 未注入 | `lock()`/`tryLockThenRun` 调用将 NPE（依赖 Spring 注入） |

== 4. 适用范围

=== 4.1 适用场景

- 非 Spring Bean 的静态代码需要加分布式锁时。

=== 4.2 不适用/边界场景

- 依赖 `lockService` 注入；独立使用（无 Spring 上下文）时不适用。
- `tryLockThenRun` 已废弃，新代码应使用 `lock()` 构建器。

== 5. 已知限制与取舍

- 静态注入依赖 Spring 容器初始化，静态方法调用前需确保注入完成。
- 历史 `tryLockThenRun` 接口保留但废弃，避免破坏既有调用。

测试内容见 `doc/design/redis/CLockUtilsTests.adoc`。
