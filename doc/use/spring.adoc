= 使用：ctool4j-spring（Spring 基础设施）

坐标：+com.c332030:ctool4j-spring+　｜　依赖：+ctool4j-core+　｜　当前基线：Spring Boot 2.7 / Spring Cloud 2021

== 一览

* *入口*：`@CSpringBootApplication`（组合注解，替代 `@SpringBootApplication`，含属性扫描与配置初始化）。
* *配置绑定*：`@CConfigurationProperties`（组合注解；只承载前缀，两个绑定开关由元注解 `@ConfigurationProperties` 给定，默认忽略未匹配属性与非法值）。
* *注入*：`@CAutowired` / `@CAutowiredScan` —— 编译期生成注入代码，**解决静态工具类无法 `@Autowired` 的问题**（依赖 +ctool4j-autowired-processor+）。
* *工具类*：`CSpringUtils`（容器/Bean）、`CRequestUtils`、`CFileUtils`、`CRestTemplateUtils`、`CSpringHttpUtils`（HTTP 报文与媒体类型）、`CIpUtils`（IP 段解析，见下）、`CAnnotationUtils`、`CAspectUtils`、`CAutowiredUtils`、`CProxyUtils`。
* *生命周期*：`ICSpringInit`（初始化回调，单例实例化完成后触发）、`ICStarted`（启动完成回调，`SpringApplication.run` 执行完成后触发）、`CStartedApplicationRunner`（启动完成后执行，回调 `ICStarted`）。
* *契约*：`ICRealClass`（真实业务类/类名/包名，带默认实现）、`ICOrdered`。
* *异常忽略*：`@CLogAndIgnoreThrowable` + 切面（记录后忽略，不中断流程）。
* *测试*：`@CTool4jSpringBootTest`。

== 用法

=== 静态字段注入

[source,java]
----
@CAutowiredScan            // 类上开启扫描（或与 @CAutowired 同用）
public class OrderHelper {

    @CAutowired
    private static OrderService orderService;   // 静态字段也可注入（编译期生成构造器注入类）
}
----

* 注解处理由 +ctool4j-autowired-processor+ 在**编译期**生成注入类，因此业务模块需确保注解处理器在编译路径上（引入 +ctool4j-spring+ 即随依赖带入）。
* 注入发生在容器初始化阶段；不要在静态初始化块中使用被注入的字段。

=== 代理场景取真实类名

公共流程（日志、幂等键、路由、指标）里 `getClass()` 在代理场景会拿到代理类，用 `ICRealClass` 或 `CProxyUtils`：

[source,java]
----
public abstract class BaseService implements ICRealClass {
    // 自动获得 getRealClass / getRealClassName / getRealPackageName，业务基类不写方法体
}

String name = CProxyUtils.getRealClassName(orderService);   // 改不了代码的对象用工具类
----

* 只支持 Spring 生成的代理（CGLIB / JDK 动态代理）；裸动态代理、MyBatis Mapper 等携带不了目标元数据，返回代理类自身。
* 适用与边界（性能、不缓存的取舍）见开发文档：link:../design/spring/real-class-name.adoc[real-class-name]。

=== 容器取值

[source,java]
----
Environment environment = CSpringUtils.getBean(Environment.class);
----

* `CSpringUtils.getBean(Class)` 优先取框架自有上下文（`CSpringConfigBeans` 持有），该上下文为空时**兜底**改用 Hutool `SpringUtil` 的静态上下文。
* 兜底的原因是两个上下文的**写入时机不同**：自有上下文经 `ApplicationContextAware#setApplicationContext` 写入，Hutool 一侧另实现 `BeanFactoryPostProcessor`、在容器刷新更早的阶段就写入了自己的 `beanFactory`。因此 `@PostConstruct`、`BeanFactoryPostProcessor` 这类**早于上下文就绪**的调用点，只有 Hutool 一侧能取到。
* **兜底有边界**：Hutool 的上下文是进程级静态字段，任何一次容器刷新都会覆盖它、容器关闭后**不清空**，直接用会取到"别的容器"或"已关闭容器"的 Bean。故兜底前先按 `ConfigurableApplicationContext#isActive` 校验其仍在活动状态；不可用或已关闭时抛 `IllegalStateException` 快速失败，不静默返回 `null`、也不取别的容器的 Bean。
* 其余入口（`getApplicationContext` / `getBeansWithAnnotation` / `newInstance`）需要完整的 `ApplicationContext`，不适用兜底。
* 业务代码**不得**直接 `ApplicationContext.getBean(...)`（绕开依赖注入、隐藏依赖关系）；容器能装配的依赖一律用构造器注入，仅静态工具类等取不到注入的场景才用本工具。

=== 启动与初始化

[source,java]
----
@CSpringBootApplication          // 启动类
public class Application { }

public class MyInit implements ICSpringInit {    // 初始化回调（单例实例化完成后触发）
    @Override
    public void init() { }
}

public class MyStarted implements ICStarted {    // 启动完成回调（SpringApplication.run 执行完成后触发）
    @Override
    public void onStarted() { }
}
----

* `onInit` 在单例实例化完成后触发；`onStarted` 在整个容器就绪、启动流程走到运行器阶段时触发，适合放"启动后一次性处理"（如释放只在启动阶段有效的缓存）。
* 回调点由 `CStartedApplicationRunner` 承载：**只实现 `ICStarted` 不产生回调**，须同时实现 `ApplicationRunner`（或直接实现 `CStartedApplicationRunner`）。
* 框架自带的清理回调：`ctool4j-spring` 的 `CSpringInit` 清 `CAutowiredUtils` 的启动期扫描包，`ctool4j-web` 的 `CWebInit` 清条件类 `ConditionalOnMissingExceptionHandlerCondition` 的声明集缓存——**清理由被清对象所在模块的 Bean 承载**（依赖方向单向）；接入方实现了 `CStartedApplicationRunner` 无需关心这些。
* 回调时序、兜底与已知限制见开发文档：link:../design/spring/started.adoc[started]。

== 配置

=== 配置属性类

配置属性类用 `@CConfigurationProperties` 声明（替代 `@ConfigurationProperties`）——本注解只承载**前缀**
一项；两个绑定开关（未知键与取值类型不匹配时如何处置）都在**元注解**上给定，默认均为忽略。

[source,java]
----
@CConfigurationProperties("order")          // 等价于 @ConfigurationProperties(prefix = "order")
@Data
public class OrderProperties {

    private Integer timeoutSeconds;
}
----

* 效果：**默认忽略未匹配的属性**（配置里多出的未知键不会让应用启动失败）与**默认忽略取值非法的属性**（类型不匹配的配置项被跳过、不中断启动）。前者沿用 `@ConfigurationProperties` 的 `ignoreUnknownFields` 默认值 `true`，后者由本注解的元注解使用点声明为 `true`（元注解默认为 `false`）。
* 属性 Bean 的注册由 +ctool4j-spring+ 的 `@ConfigurationPropertiesScan`（扫描 `com.c332030.ctool4j`，`@CSpringBootApplication` 亦已开启）承担，属性类**只需声明注解**，不必再写 `@EnableConfigurationProperties`。
* 需要**强校验**（未知键或非法值即启动失败）时，本注解表达不了——它只有一个属性元素，改用元注解：`@ConfigurationProperties(prefix = "order", ignoreUnknownFields = false)`、`@ConfigurationProperties(prefix = "order", ignoreInvalidFields = false)`。
* 默认忽略的代价：**配置键拼写错误（静默取默认值）与配置值类型写错（该项被跳过）都不会在启动期被发现**，需要暴露时按上一条改用元注解。

|===
| 配置 | 说明
| +spring.application.*+ | `CSpringApplicationConfig`（`group` / `name` 等应用级配置）
| +spring.jackson.json5+ | 为 true 时用 Jackson 的 JSON5 支持并同步配置容器内 `ObjectMapper`
|===
