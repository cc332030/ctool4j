= ctool4j 使用文档（AI 使用说明）

本目录是 ctool4j 的**使用文档**：面向「其他项目 + 其 AI」——拿到本库后**有哪些能力、怎么引入、怎么用、有哪些坑**。

* *读者*：引用本库的项目的开发者与其 AI；**不需要**了解本库内部实现（内部设计见 link:../README.adoc[开发文档]，本目录与之**隔离**）。
* *正文单位*：**按依赖坐标成篇**（一个 Maven 构件一篇），因为调用方是按构件引入的。
* *覆盖范围*：全部对外构件（含空占位、已废弃）；一篇正文覆盖一个或多个坐标，由下表指明。
* *阅读方式*：AI 可**只读**「客户端引入」+ 所需构件对应的那一篇；无需通读。坐标与模块目录的对应关系见 link:../dependency.adoc[模块间依赖关系]（那是依赖关系的唯一视图，本目录不重复）。

== 客户端引入（先读）

=== 引入依赖

. 引入 BOM 统一版本（第三方与 ctool4j 构件版本都由它管，业务侧不写版本号）：

[source,xml]
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.c332030</groupId>
            <artifactId>ctool4j-bom</artifactId>
            <version>1.1.20260730-SNAPSHOT</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
----

. 按需引入构件（省略 `<version>`）：

[source,xml]
----
<dependency>
    <groupId>com.c332030</groupId>
    <artifactId>ctool4j-core</artifactId>
</dependency>
----

`<version>` 取当前发布版本；上述两处坐标亦可替换为各构件自己的 +ctool4j-dependencies+ 版本。模块间依赖关系见 link:../dependency.adoc[doc/dependency.adoc]。

=== 版本号取已发布的 release

`<version>` 取**已发布的 release 版本**（当前基线为 +1.1.x+）；上例中的 +-SNAPSHOT+ 仅是本项目内部开发版本，业务项目**不要**依赖快照。同一 BOM 号即一套配套校验过的构件组合，故**升版本只改 BOM 一处**，各构件不写版本号。

== 客户端须遵循的规范

本库的能力与约定（工具类语法糖、命名前缀、分层落点等）由一套规范定义，**引用本库的项目的代码与 AI 都应按它执行**；不引用会导致「用了库但写法不统一」，这正是本目录各篇「注意/误用点」的判据来源。

[cols="1,3", options="header"]
|===
| 规范 | 说明

| 规范入口
| +https://agent.c332030.com/AGENTS_COMMON.adoc+（远程静态路径，直接可读）——规范以「分类 + 懒加载」结构存放于其同级 +specs/+ 下：先读入口的加载调度规则，再按本次操作涉及的主题加载对应文件（如写 Java 前加载 +specs/stack/java.adoc+、写文档前加载 +specs/general/doc.adoc+）。

| 项目特有规范
| 本项目自身的命名前缀（类 +C+、纯字段接口 +IC+）、C 工具类语法糖、参数校验 +CValidUtils+、Java 8 目标版本等，见 link:../../agent/AGENTS-PROJECT.MD[agent/AGENTS-PROJECT.MD]。
|===

* *冲突次序*：本项目特有规范优先于远端统一规范；但**引用方项目自身的规范**（引用方根目录的 +AGENTS.adoc+ 之类）优先于上述两者——引用方自己维护的规则才是其最终口径。
* *落地形态*：引用方把规范入口写进自己的 +AGENTS.md+ / 项目规范即可，**不需要**把规范文件复制进引用方仓库（复制即第二真源，改一处必漏一处）。

== 约定（本目录通用）

* *冒号前缀 = 依赖坐标*：正文标题的 +ctool4j-xxx+ 即 Maven artifactId，groupId 一律为 +com.c332030+。
* *默认自动装配*：能 Spring 自动装配的构件，引入依赖后**无需手工 `@Bean`**（个别需继承装配基类的已在正文标明）。
* *配置前缀*：各构件以 `c-` / 自身命名空间为前缀的属性在正文「配置」节列出。
* *深入一层*：类级与方法级内容（参数、返回、异常、边界、默认值）在各源码 javadoc；跨类的方案取舍与已知限制在 link:../README.adoc[开发文档]的对应设计文档——本目录只给「怎么用」，重复即漂移，故不复制。
