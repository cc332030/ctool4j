= ctool4j

Java 工具库，面向 Spring Boot 2.7 / Spring Cloud 2021 生态，提供 Web、认证、缓存、数据库、日志、消息、任务、文件等场景的组件化封装与约定式开发支持。

== 模块全景

项目采用「构建基础设施 + 组件模块」两层结构：

[source,text]
----
ctool4j（根，packaging=pom）
├── ctool4j-dependencies     BOM：统一管理 ctool4j 自研模块版本
├── ctool4j-bom              BOM：统一管理第三方依赖版本（含 import 上面的 dependencies）
├── ctool4j-processor-pom    编译期注解处理器（代码生成）
└── ctool4j-parent
    └── ctool4j-component
        ├── 基础层    definition / core / http-pom（http-base / http-javax / http-jakarta）/ db / transaction
        ├── Spring 层 spring-base-pom（spring-base / spring-javax / spring-jakarta / spring-security-base / spring-security-javax / spring-security-jakarta）
        │             spring-pom（spring / spring-security / spring-cloud）
        ├── 应用层    web / feign / redis / cache
        ├── 认证层    auth-pom（auth-base / auth-spring）
        ├── 中间件层  log-pom / mybatis-pom / nacos-pom / mq-pom / job-pom
        ├── 文件层    file-pom（csv / excel / minio）
        └── 配套层    doc-pom / test-pom
----

== 构建基础设施

- *ctool4j-dependencies*：BOM，统一声明全部 ctool4j 自研构件的版本。
- *ctool4j-bom*：BOM，统一管理第三方依赖版本（Spring Boot / Spring Cloud / MyBatis-Plus / Redis / MQ / 工具库等），并 import +ctool4j-dependencies+。业务项目引入该 BOM 即可获得一致的依赖版本，无需手写版本号。
- *ctool4j-processor-pom*：编译期注解处理器，通过 SPI 自动注册，被组件模块用作 annotation processor：
  - +ctool4j-autowired-processor+：处理 +@CAutowired+ / +@CAutowiredScan+，为静态字段生成构造器注入类（解决 Spring 静态工具类无法 +@Autowired+ 的问题）。
  - +ctool4j-mybatis-processor+：处理 +@CAutoBizService+，根据业务实体接口的 getter 自动生成业务 Service 接口（含按业务 ID 的增删改查 default 方法）。
  - +ctool4j-mq-processor+：占位，待实现。

== 项目支撑目录

除 Maven 模块外，项目根下还有以下支撑目录：

- *agent/*：项目规范目录。规范以远端统一规范（+http://agent.c332030.com/AGENTS_COMMON.adoc+，含 `specs/` 分层规范）为基准，入口为根 +AGENTS.md+；项目特有规范集中在 +agent/AGENTS-PROJECT.MD+。涉及某主题操作前须按加载调度规则加载对应规范文件确认规则。
- *doc/*：项目文档目录（AsciiDoc），**只放总结性与规划性文档**。按「javadoc 按层次承载、文档目录只放总结」分层：
  - **源码 javadoc 承载类级与方法级内容**（javadoc 即文档）：**类上方写总结**（定位、能力目录、设计思路总述）；
    **方法上方写详细设计与详细步骤**（流程步骤、参数/返回值/异常契约、边界与默认值、兜底、易误用点）。
  - **测试类同样分层**：**测试类上方写总结**（测试设计思路与依据、覆盖与未覆盖、用例总览/分类/编码与逐个用例精简总结）；
    **测试方法上方写详细设计**（引用用例编码、测试意图、测试范围、测试意义、断言取舍）。
  - +doc/design/<模块>/<功能>.adoc+：**跨类的功能/模块级**设计文档（方案取舍、兜底策略、适用范围、已知限制与波及影响），
    按功能命名、不与源文件同名；类级细节一律链接到对应源码 javadoc。
  - +doc/README.adoc+：**全项目文档导航入口**（逐级指向模块 README 与功能文档的固定落点）；各级 +doc/README.adoc+ 索引页只在确有下级内容处保留。
  - 源文件版本由各源码 javadoc 的 +@version+ 维护；全项目变更记录统一在 +CHANGELOG.adoc+（按版本分组、版本内分类）。
  - 除上述总结/规划性文档（含各级 README）、+CHANGELOG.adoc+、+TODO.adoc+ 与规范文件外，仓库不再保留其他文档。
  配套规范见远端统一规范的文档规范与 link:agent/AGENTS-PROJECT.MD[项目特有规范]。
  - +doc/dependency.adoc+：**模块间依赖关系的唯一视图**（全项目模块清单 + UML 依赖图 + 直接依赖表）；判断「某模块能不能依赖某模块、新依赖该不该加」以它为准。
  - +doc/compatibility.adoc+：**依赖升级兼容性 / 已知问题的唯一登记处**（当前面向 Spring Boot 2.x → 3.x / JDK 17）；已登记条目 code review 时不再作为问题提出。
  - link:doc/use/[+doc/use/+]：**使用文档（面向引用本库的其他项目与其 AI）**，整体开放为静态服务；与开发文档（+doc/+）**隔离**——
    使用文档只答「有哪些能力、怎么引入、怎么用、有哪些坑」，开发文档承载内部实现与设计取舍（见「使用说明」）。
- *script/*：项目级脚本
  - +clean-tmp.py+：清理 +tmp/+ 下的临时产物（扫描中间结果、日志等），仅限 +tmp/+ 目录，带路径穿越防护。
  - +push-origins.bat+：推送所有 origin 远端。
- *tmp/*：临时产物目录（扫描中间结果、日志、临时规划等），不纳入版本管理、不提交；由 +script/clean-tmp.py+ 清理，故不单独登记。
- 根级文档：+CHANGELOG.adoc+ 为项目统一变更日志（按版本分组、版本内按模块与变更类型分类）；+TODO.adoc+ 为项目待办清单；+AGENTS.md+ 为规范入口（引用远端统一规范 + 项目特有规范，见 +agent/+）。
