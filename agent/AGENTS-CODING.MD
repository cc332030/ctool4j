
# 通用编码规范

以下规范适用于所有编程语言。

## 代码复用

- 避免重复写相同代码：相同的代码逻辑抽离为公共方法，或移动到下游公共流程统一处理，不复制粘贴
- 一个对象需要初始化多个值且多处频繁调用时，优先抽离出公共方法（工厂方法/初始化方法）统一创建，避免重复初始化代码

## 警告与弃用

- 警告处理：除非显式声明（如代码注释说明该警告已知且接受），否则严禁遗留任何警告（编译警告、javadoc 警告、IDE 警告等）——警告虽不影响编译甚至运行，但特定场景下与报错无异，必须像解决报错一样解决；新代码不得引入警告，存量警告须修复或声明；javadoc 警告同样须处理，因代码问题本身无法解决的除外（须在代码注释说明原因）
- 兼容老代码无法避免的警告（如弃用 API 因低版本依赖无法替换）：须在代码注释说明原因并抑制（如 @SuppressWarnings），避免反复提醒；为兼容低版本而保留的旧 API 告警是正常且必要的（如 MyBatis-Plus 同时兼容 3.3/3.4/最新，默认引入最新仅编译），不属于需修复的警告
- 内部弃用 API 的调用不迁移、不修复：本项目自研的废弃 API（@Deprecated，如 CLockUtils 弃用方法）被项目内部调用时，调用处保持原样，产生的弃用警告已知且接受（内部废弃 API 随时会被移除，迁移收益低且可能引入回归，见 AGENTS.md 废弃方法规则）；仅第三方库弃用 API 须升级到新签名（如 feign 11 起 Request.create 5 参改 6 参）

## 表达式与调用写法

- 实参不内联复杂逻辑与对象：方法调用实参（含集合 add、stream map、new 构造、builder/配置器等 DSL 链式调用的设置值处）只传简单值或已算好的局部变量，不内联复杂逻辑（如三元表达式、方法调用嵌套、多级 `.xxx()` 串联），也禁止内联 `new Xxx(参数...)`、`Xxx.builder()...build()` 等对象初始化后直接作为入参——复杂计算与对象必须先创建为局部变量再传入；`new Xxx()`（无参构造）除外。识别特征：单行内嵌套多层方法调用/构造（如 `entries.add(new ToMapEntry(field, CMethodHandleUtils.getGetterHandle(field).asType(CMethodHandleUtils.GETTER_HANDLE_TYPE)))` 应拆为取 handle 局部变量后再 add）、同一表达式内连续换行的 `.method(...)` 链、以 builder/configure 等命名或以返回自身（return this）为特征的构造器方法
- 三元表达式（三段式）只用于简单判断（如单个 null 兜底）；复杂逻辑（嵌套三元、多分支、含长方法调用）改用 if-else，可读性优先于行数

## 类设计

- bean/model/pojo 等纯数据结构类中不写逻辑：仅保留字段与简单的字段读写，不做计算、组装、格式转换、对外部对象（如工具类、请求对象）的访问；需要时下沉到工具类或独立服务。识别特征：以 bean/model/pojo/dto/vo/entity 等结尾的类、或仅使用 @Data 等访问器注解的类，其方法中出现非字段读写的计算/转换/组装逻辑
- 有开关（enable/switch 等布尔配置项）控制的逻辑：先判断开关，开关关闭时直接跳过，不在开关外做耗时操作（如取时间戳、拼字符串、访问外部资源），开关关闭即零成本。识别特征：布尔配置项之后接的代码块，整段逻辑应包在开关判断内或开关判断前置 return，开关判断置于最前

## 命名与代码质量

- 命名前缀：当前项目所有类（class）统一使用 `C` 固定前缀，所有接口（interface）统一使用 `IC` 固定前缀；新增、重构代码均须遵循
- 类重名：除非类全名（全限定类名）冲突不可避免，否则不使用类重名；发现类重名的需调整优化
- NPE 原则：NPE 问题原则上必须修复（存在取舍时，在代码注释中说明取舍依据与边界）
- 兼容性与平衡：Java 跨平台，不得因局部小优化牺牲兼容性（JDK 版本、操作系统、环境依赖等）；优化与健壮性、可维护性、实用性之间保持平衡，目标始终是更好维护、代码更健壮、实用性更好
- 工具类排序（大小 + 时间 + 复杂度，可同处一个类）：工具类的字段/方法顺序存在可排序维度时，按下述规则排列，多个维度可同时应用于同一类——
  - 按大小：字段/方法按基本类型重载/分组（如判空、转换等方法，对象本身或数组均可，数组可选）时，按可存储数据大小/位宽顺序排列——整数类型按位宽递增（byte、short、char、int、long），随后浮点按位宽递增（float、double），再 boolean（特殊仅两值），最后 Object（引用类型）
  - 按时间：字段/方法存在逻辑时序（如流程步骤、数据加工阶段）时，按流程走过的先后顺序、数据加工在流程中的处理顺序排列——先发生的在前、后发生的在后，与业务执行次序一致
  - 按复杂度：字段/方法按实现/使用复杂度排列时，简单的在前、复杂的在后（如基础能力在前、组合/高级用法在后）
  - 不按使用频率、字母序或历史追加顺序随意摆放
