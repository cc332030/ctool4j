= 变更日志

本文件为 ctool4j 项目的统一变更日志，按时间**倒序**记录（最新在最上方）。版本号在各源文件的 javadoc `@version` 中维护。

- 1.1 | 2026-09-14 | `CAssert` 新增按数据类型分派的有效性断言 `valid` / `notValid`（各带 `String` 与 `Supplier<String>` 重载），参数类型重载覆盖 Object、CharSequence、Iterable、Collection、Map 与 9 种数组，语义与 `CValidUtils#isValid/isNotValid` 一致（字符串按 blank、集合/Map/数组按 empty、其他对象按 null）；`notEmpty` / `notBlank` 实现改为复用 `CValidUtils`，对外语义不变
- 1.1 | 2026-09-14 | `CAutowiredScanConfiguration` 显式声明 `@Configuration(proxyBeanMethods = false)`：该类自身是 `BeanDefinitionRegistryPostProcessor`，容器在后置处理器阶段即实例化它、早于 CGLIB 增强，Spring 会打印 "singleton instance has been created too early" 的 INFO 并跳过增强；关闭方法代理可消除该日志（本类无 `@Bean` 方法，行为不变，日志提示里的"典型原因"与本类无关）
- 1.1 | 2026-09-14 | 新增 `CAbstractAuthConfiguration`（auth-base 认证装配基类）：业务未自建 mock 会话配置时提供关闭态默认 bean（`enable=false`、`session=null`），业务子类加 `@Configuration` 继承其 `@Bean` 方法并固定会话类型；`@Bean` 方法名按规范以 `c` 前缀命名（bean 名 `cSessionMockConfig`）；补齐类文档（含 `@Configuration` 注释原因、`@ConditionalOnMissingBean` 的顺序敏感性）与装配测试 4 例
- 1.1 | 2026-09-14 | 修复会话读回故障（`CAbstractBaseAuthFilter : loadAuthentication error`）：`ICSecuritySession#getAuthorities()` 默认实现不再返回共享常量——Jackson 的 `MapperFeature.USE_GETTERS_AS_SETTERS`（`SetterlessProperty`）会把 JSON 中的 authorities 合并进 getter 的返回值，共享不可修改常量会抛 `UnsupportedOperationException`，共享可变常量则被逐次追加而污染全局；改为返回一次性副本，会话自身持久化权限（有可写成员）仍走 setter 路径不受影响。陷阱说明见 link:doc/design/spring/authority-json.adoc[会话权限的 JSON 读写]
- 1.1 | 2026-09-14 | 修复会话含权限字段的 JSON 反序列化失败（`GrantedAuthority` 为接口、JSON 无类型信息导致 `InvalidDefinitionException`）：`ctool4j-spring-security` 新增 `CSecurityJacksonModule`（接口与 `SimpleGrantedAuthority` 同注册反序列化器）并以 `META-INF/services/com.fasterxml.jackson.databind.Module` 声明为 Jackson SPI，由 `ObjectMapper#findAndRegisterModules()` 自动装配；新增权限常量池 `CGrantedAuthorityUtils`（同 authority 全局复用同一实例），反序列化与匿名权限统一取自常量池（`ANONYMOUS_AUTHORITIES` 一并改为不可修改集合）；序列化沿用 Jackson 原生形态 `{"authority":"ROLE_XXX"}`（不引入 default typing 的 `@class`）；匿名权限名落为 `CSpringSecurityUtils.ROLE_ANONYMOUS` 常量（Spring 官方未提供该常量，取值以其实现为准）。设计说明见 link:doc/design/spring/authority-json.adoc[会话权限的 JSON 读写]
- 1.1 | 2026-09-13 | `CAbstractBaseSessionService#getDefaultNull` 由包私有放宽为 `public`：业务侧可在任意包直接继承会话服务基类（原仅限 `com.c332030.ctool4j.session.service` 包）
- 1.1 | 2026-09-13 | 文档导航收敛为单一入口：删除 48 个模块级 `doc/README.adoc` 重复索引页（模块级内容归模块 README、功能级归 `doc/design/`、依赖归 `doc/dependency.adoc`），`doc/README.adoc` 改为全项目文档导航入口；`ctool4j-spring` 的 `perf.adoc` 移至 `doc/design/spring/spring-perf.adoc`（功能级文档统一落点）
- 1.1 | 2026-09-13 | 新增模块间依赖关系文档 link:doc/dependency.adoc[doc/dependency.adoc]（唯一视图，含全部模块清单与 UML 依赖图），原 README 的文字版依赖描述改为指向该文件
- 1.1 | 2026-09-13 | `CAbstractBaseSessionService#getDefaultNull` 由包私有放宽为 `protected`：业务侧可在任意包直接继承会话服务基类（原仅限 `com.c332030.ctool4j.session.service` 包）
- 1.1 | 2026-09-13 | 破坏性变更：`CAbstractJwtFilter` 改名 `CAbstractWebAuthFilter` 并下沉到 ctool4j-web，`CSecurityConfiguration` 改按该类型注入认证过滤器，引用方需改 import
- 1.1 | 2026-09-13 | 新增 `CAbstractBaseAuthFilter`（ctool4j-auth-base）：抽离认证过滤器中与 Spring Security 无关的过滤器骨架、mock 会话加载与会话加载，Security 认证构造留在 auth-spring 子类；mock 开关为 null 视为未启用（修复拆箱 NPE），并补链路单元测试
- 1.1 | 2026-09-13 | 测试口径明确为「只保证 JDK 8 编译」：`CClassUtilsTests` 样本用仅 JDK 8 存在的 `jdk.Exported`（该类型 JDK 9+ 已移除，测试代码在 JDK 9+ 无法编译），并在类级备注该约束；`compareField` 由空断言改为可观察行为断言
- 1.1 | 2026-09-13 | 性能测试可显式触发：新增 `perf` profile，`mvn -Pperf -Dtest=<XxxPerfTests> test` 才能真正执行（`surefire` 的 `excludes` 优先于 `-Dtest`，此前文档给的触发命令实际无效）
- 1.1 | 2026-09-13 | 测试类命名随动迁移为 `Tests` 定式（7 个）：`CBeanUtilsTests`、`CExceptionUtilsTests`、`CBiFunctionTests`、`CTriFunctionTests`、`CLogUtilsTests`、`CStrUtilsTests`、`CCoreTests`
- 1.1 | 2026-09-13 | 修正文档与测试用例编号不一致：`ctool4j-core` README 的校验工具改为 `CValidUtils`（`CValidateUtils` 已废弃）；`CBeanUtilsTests` 类索引改为标注各用例实际所属测试类
- 1.1 | 2026-09-12 | 破坏性变更：`CIdUtils.UUID`/`simpleUUID` 默认改为随机 UUID v4，不再时间有序且随机源非密码学安全；原 UUID v7 逻辑改为 `UUIDv7`/`simpleUUIDv7`，需要可排序 UUID 的调用方须改用新方法
- 1.1 | 2026-09-12 | 新增 `ICRealClass` 契约（`ctool4j-spring` 的 `interfaces` 包）与 `CProxyUtils` 代理解析类（`ctool4j-spring`）：代理场景下取真实业务类/类名/包名，契约带默认实现、业务侧不写方法体；热路径按「非 Spring 代理快速返回 + 惰性解包装」解析，单次成本纳秒量级（Spring JDK 代理较原实现降约一半）
- 1.1 | 2026-09-11 | 修复并行构建下自动注入偶发失败，业务模块无需额外配置即可生效
