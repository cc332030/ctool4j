本文件是 ctool4j 的变更日志，**按版本分组、版本内按模块与变更类型分类**：版本号即发布 tag（CalVer，`<主>.<次>.<yyyyMMdd>`），日期取 tag 创建日（ISO 8601）。
条目写「给引用方带来什么影响」（对外可见的能力、契约、默认值、配置、坐标），不写实现过程；内部重构、测试补强、文档搬家等对外无感知的改动只在其产生可感知结果时记录。
破坏性变更以 [.breaking]#破坏性变更# 标注，须按「影响」列的迁移方式处理。

== 1.1.20260730

*发布日期：2026-09-18 ｜ 上一版本：1.0.20260715（2026-07-30）*

本版本是本项目截至目前改动最大的一个版本：认证组件重构为分层模块、缓存新增主动失效注解、Redis 新增限流与幂等、代理解析与 UUID 语义调整；期间还完成了一次全局文档与规范收敛，并出现 8 项破坏性变更（见下表标注）。

[cols="1,3,4", options="header"]
|===
| 类型 | 变更点 | 影响

| [.breaking]#破坏性变更#
| `ctool4j-core`：`CIdUtils.UUID()` / `simpleUUID()` 默认实现改为随机 UUID v4
| 默认值不再时间有序、随机源非密码学安全；需要可排序 UUID 改用 `UUIDv7()` / `simpleUUIDv7()`（原 v7 逻辑迁入，仍依赖可选依赖 `java-uuid-generator`）。**不得**用于令牌、密钥、会话 ID 等安全场景

| [.breaking]#破坏性变更#
| `ctool4j-core`：`CBeanUtils.copy` 系列对集合/Map/数组/Bean/Date 字段改为**深拷贝**
| 由「跳过 / 共享引用」改为递归深拷贝（元素与键值递归，环状与跨字段共享引用只拷一份）。需要保留共享引用的调用方须改用 `toMap` 或在复制后自行恢复；**跨接口容器（如源 `List` → 目标 `Set` 声明）按目标声明类型重建容器写入**（支持，不再跳过）

| [.breaking]#破坏性变更#
| `ctool4j-web`：`CAbstractJwtFilter` 改名 `CAbstractWebAuthFilter`
| 类下沉到 `ctool4j-web`，`CSecurityConfiguration` 改按该类型注入认证过滤器；引用方须改 import

| [.breaking]#破坏性变更#
| `ctool4j-spring-security`：`CSpringSecurityUtils#writeJsonError` 两个重载去掉 `HttpServletRequest` 入参
| 认证错误响应的 message 不再拼接 requestURI（路径与查询串均不进入响应体），文案只由入参决定；3 个处理器（`CAccessDeniedHandler`、`CAuthenticationEntryPoint`、`CSessionInformationExpiredStrategy`）调用方同步

| [.breaking]#破坏性变更#
| `ctool4j-doc-openapi2`：文档配置键名 `c-doc.openapi2` → `doc.openapi2`
| 引用方若有该配置前缀须改名，否则配置不生效

| [.breaking]#破坏性变更#
| `ctool4j-web`：`CRequired` 必填校验迁入本模块（`CJwtUtils` 同期归位到 `web`，供全量组件复用）
| 引用方的依赖坐标与 import 随迁移调整，否则编译不到对应类型

| [.breaking]#破坏性变更#
| `ctool4j-core` → `ctool4j-spring`：`CProxyUtils` 迁入 `spring` 模块
| 引用方须改 import 与依赖坐标（`ctool4j-spring` 已在依赖链中时只需改 import）

| [.breaking]#破坏性变更#
| 日志模块迁移：请求日志、traceId 透传、MDC（`CRequestLogUtils`、`CTraceUtils`、`CMdc` 等）由 `ctool4j-log-*` 迁入 `ctool4j-web` / `ctool4j-logback` / `ctool4j-log4j`
| 引用方须按新坐标与包名调整 import；`ctool4j-web` 自带 `CRequestLogConfig` / `CRequestLogBaseConfig` 装配入口

| 新增
| `ctool4j-core`：`CBeanUtils` 支持跨接口容器（源 `List` → 目标 `Set` 声明）与一次性视图（`Iterator` / `Stream`）——按**目标声明类型**重建容器
| 跨接口容器不再「跳过不写入」，该字段照常写入（有序优先：目标 `Set` 建 `LinkedHashSet`、`Map` 建 `LinkedHashMap`、`List`/`Collection` 建 `ArrayList`）；目标声明为具体实现类（如 `ArrayList` 源 → `LinkedList` 目标）时按其重建。此前会被静默跳过、字段为空，排查字段缺失时看这里

| 修复
| `ctool4j-core`：`CBeanUtils` 跨容器族的容器声明（源 `List`/`Set` → 目标 `Map` 声明，或反向）改为整条跳过、不再抛异常
| 该场景此前会把拷贝体按目标族归一后仍按源码形态强转，抛 `ClassCastException`（被吞成 debug 日志）；另有一处把源运行时类写进目标声明族的 setter、在 MethodHandle 签名层抛异常。两者在集合类源（如 `Collections.emptyList()`）命中 Map 声明字段时每次复制都触发。现按「跳过不写入、字段保持既有值」处理，与跨接口容器的旧语义一致

| 修复
| `ctool4j-core`：`CBenchmarkReport` 基线均值为 0 时不再输出 `NaN`/`Infinity`
| 相对基线与吞吐此前按 `x/0` 取值，渲染成 `NaNx`/`Infinityx` 与 `Infinity`——会被误读为"极快/极慢"，实际是基线无有效耗时、比值无意义；现按「不可比」输出文字

| 修复
| `ctool4j-core`：`CReflectUtils` 构造器查询只取 public 构造器
| 包私有/受保护构造器此前取不到（`Class#getConstructors()` 只返回 public），导致这类类被判为「不可实例化」；现按 `Class#getDeclaredConstructors()` 取全部构造器（本工具类已 `setAccessible`），可实例化范围恢复正确

| 新增
| `ctool4j-core`：`CBeanUtils` 新增「不支持的目标类集合」——有无参构造但构造体必定抛异常的目标类，首次实例化失败即登记（打一次 error 日志），其后该类型一律跳过不写入、不再重复报错
| 此前每次都重新反射构造、重新抛异常、重新打日志（热路径上退化成「每次一个异常」）；注意被跳过的类型其字段保持目标对象既有值（不是共享引用）。无可用无参构造的类仍按共享引用处理（只打一次 debug）

| 新增
| `ctool4j-core`：`CUnauthorizedException`（不携带错误码，语义为「未认证」）
| 未认证与普通业务失败区分开；配套 `ctool4j-web` 的 `CUnauthorizedExceptionHandler` 返回响应体业务码 401 + HTTP 状态 401，调用方以响应体业务码 401 识别未认证（见 link:doc/design/web/unauthorized-401.adoc[未授权统一返回业务码 401]）

| 新增
| `ctool4j-redis`：`@CRateLimit` 限流注解与 `CRateLimitAspect`
| 按业务 id（el 表达式，空则按方法全局限流）+ 窗口次数/秒数限流，超阈值抛 `CRateLimitException`。固定窗口计数，窗口临界点可能瞬时冲过阈值一次；同名重载方法共用同一 key（见 link:doc/design/redis/rate-limit-idempotent.adoc[限流与幂等]）

| 新增
| `ctool4j-cache`：`@CCacheRemove` / `@CCacheUpdate` 注解
| update/delete 方法执行成功后主动更新/删除缓存，不必等过期；方法抛异常时不删不写，update 返回 null 不写，key 解析为 null 时跳过

| 新增
| `ctool4j-redis`：`@CIdempotent` 幂等/防并发注解
| 同一业务 key 任一时刻只允许一个调用执行业务，其余并发或重复调用抛 `CIdempotentException`，防重复提交与并发穿透；幂等 key = 应用前缀 + 分组类简单名 + 方法名 + 业务 id，业务 id 用 el 表达式从方法参数取值

| 新增
| 日志能力——`ctool4j-core`：`CLogUtils` 的 JSON 日志分支；`ctool4j-definition`：`@CLogSensitive` 敏感字段脱敏、`@CLogBlob` 大字段截断
| 日志专用 mapper 输出时按注解脱敏（默认保留前 3 后 4 位，长度不足全部打码）与截断大字段；**全局 ObjectMapper 无此行为**，业务序列化仍输出真实内容

| 新增
| `ctool4j-core`：`CElKeyResolveUtils`（el 表达式解析/取值，由 cache 模块的 `CCacheKeyResolver` 迁入并更名，去掉 spring-core 依赖）
| 缓存与限流复用同一套 el 解析，业务侧可用 `参数名.属性…` 形式取业务 id

| 新增
| `ctool4j-spring`：`ICRealClass` 契约与 `CProxyUtils`（由 `ctool4j-core` 迁入本模块）
| 代理（CGLIB / JDK 动态代理）场景下取真实业务类/类名/包名；热路径按「非 Spring 代理快速返回 + 惰性解包装」解析，单次成本纳秒量级。非 Spring 生成的代理（裸 `Proxy.newProxyInstance`、MyBatis Mapper 等）返回代理类自身、不猜测业务类型；`spring-core` 为 provided，首次调用按类加载器可达性判定（见 link:doc/design/spring/real-class-name.adoc[真实业务类/类名/包名]）

| 新增
| `ctool4j-auth-pom`：认证拆分为 `auth-base`（过滤器骨架、mock 会话加载、会话加载）与 `auth-spring`（Security 认证构造）两个模块
| 引用方按需选择坐标；框架层能力从业务实现中分离

| 新增
| `ctool4j-auth-spring`：`CAbstractAuthConfiguration` 装配基类
| 提供默认认证过滤器 bean（`cAuthFilter`），匿名判定收口为 `protected` 模板方法 `isAuthAnonymous`（子类必然跨包，故为 `protected`）；业务自建同类型过滤器时不覆盖。配套 `CAbstractAuthBaseConfiguration`（auth-base）在业务未自建 mock 会话配置时提供关闭态默认 bean（`enable=false`、`session=null`）

| 新增
| `ctool4j-spring-security`：`CSecurityJacksonModule` + `CGrantedAuthorityUtils` 权限常量池
| 会话含 `GrantedAuthority` 字段的 JSON 读写可用（接口类型无 `@class` 也能反序列化，序列化沿用 `{"authority":"ROLE_XXX"}` 原生形态）；同 authority 全局复用同一实例（见 link:doc/design/spring/authority-json.adoc[会话权限的 JSON 读写]）

| 新增
| `ctool4j-web`：`CHttpMessageNotReadableExceptionHandler`、`CMissingServletRequestParameterExceptionHandler`、`CMethodArgumentTypeMismatchExceptionHandler`
| 请求体缺失/不可读、必填参数缺失、参数类型不匹配不再落兜底处理器返回「未知异常」；文案保留参数名、不透出类型名与嵌套异常，客户端问题降为 debug 日志

| 新增
| `ctool4j-core`：`CList` / `CMap` / `CSet` 的不可变实时视图（`CListView` / `CMapView` / `CSetView`）、`CLog` 按级别打印
| 持有可变实例同时暴露不可变视图；日志可按 `Level` 选择打印方式（null 兜底 error）

| 新增
| `ctool4j-definition`：语义接口 `ICToken`、`ICCreateMillis`；`ctool4j-auth-base`：`CAuthUtils`；`ctool4j-web`：`CTokenUtils`

| 新增
